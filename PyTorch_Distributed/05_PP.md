### 1. 什么是 Pipeline Parallel (PP)? 具体含义是什么?

#### 核心定义

流水线并行(Pipeline Parallelism, PP)是一种按模型的网络层(Layer-wise / Inter-layer)纵向切分模型的分布式技术.

简单来说: 如果一个神经网络有 64 层 Transformer Block, 我们可以把前 16 层放在 GPU 0, 17–32 层放在 GPU 1, 33–48 层放在 GPU 2, 49–64 层放在 GPU 3. 每个 GPU 负责模型的一个"阶段"(Stage).

#### 与其它并行范式的区别

* 数据并行 (DP/DDP/FSDP): 每张卡都持有完整的模型(或分片参数), 但输入不同的数据切片(Data-split).

* 张量并行 (TP): 单层(如矩阵乘法 $Y = XW$)切分到多张卡上协同计算(Intra-layer split).

* 流水线并行 (PP): 按层深度将模型切成不同段落分配给不同卡(Inter-layer split).

#### 关键机制与核心概念

如果只是简单地把模型切段, GPU 0 计算完才能轮到 GPU 1, 会导致严重的时间浪费(GPU 处于空闲等候状态). 为了解决这个问题, PP 引入了工厂流水线(Assembly Line)的思想:

1. Micro-batch(微批次):

    * 将原本的一个训练大 Batch(Mini-batch)切分为多个更小的 Micro-batches(比如切成 4 个或 8 个).

    * 当 GPU 0 完成 Micro-batch 0 的前向计算后, 立即将其激活值(Activation)发送给 GPU 1; 同时 GPU 0 紧接着开始计算 Micro-batch 1, 而 GPU 1 开始计算 Micro-batch 0. 这样所有 GPU 就能"同时有活干".

2. Pipeline Bubble(流水线气泡):

    * 流水线刚启动(Warmup)和即将结束(Flush)时, 由于存在数据依赖, 部分 GPU 必须等待前面/后面的 Stage 计算完成, 这段 GPU 闲置的时间被称为"气泡".

    * Micro-batch 数量越多, 气泡占比越小, GPU 利用率越高.

3. 调度策略(Pipeline Schedules):

    * GPipe: 先完成所有 Micro-batches 的前向传播(Forward), 再集中做反向传播(Backward). 缺点是需要驻留大量的激活值显存.

    * 1F1B (One Forward, One Backward): 在前向"填满"流水线后, 每做一次前向传播立即做一次反向传播. 这能大幅降低激活值占用的显存峰值, 是目前最常用的调度策略.

    * Interleaved 1F1B(交错式 1F1B): 单张 GPU 分配多个非连续的 Stage(例如 GPU 0 负责第 1 层和第 9 层), 进一步缩小 Pipeline Bubble 的比例.

### 2. 为什么需要 Pipeline Parallel (PP)?

在拥有张量并行(TP)和全参数重分片数据并行(FSDP/ZeRO-3)的今天, 我们为什么依然离不开 PP? 原因主要有以下三点:

#### (1) 突破显存极限与规模扩展

千亿/万亿参数的模型(如 405B 参数需要至少 800GB 显存仅用于存放 FP16 权重, 加上 Optimizer States 和 Activations, 可能需要数 TB 显存)无法存放在单张甚至单台服务器(如 8 卡 H100)的显存中. 必须将模型纵向深度切分到成百上千张卡上.

#### (2) 极高的跨节点(Inter-node)通信效率

这是 PP 最核心的物理优势:

* TP(张量并行): 每经过一层 Transformer 层就需要进行 2 次 All-Reduce(或 All-Gather/Reduce-Scatter). 通信频率高、传输数据量大, 必须依赖 GPU 节点内部的高速 NVLink 互联(百 GB/s 级带宽). 如果跨节点做 TP, 网络延迟和带宽会成为致命瓶颈.

* PP(流水线并行): 仅在相邻 Stage 的边界处进行 P2P(Point-to-Point, Send/Recv)通信. 它只传输单个 Micro-batch 的激活值/梯度, 通信量极小. 因此, PP 非常适合跨服务器节点(通过相对较慢的 InfiniBand 或 RoCE 网络)扩展.

#### (3) 构建 3D 并行(Composability)

在超大模型训练实践中(如 Megatron-LM 或 PyTorch TorchTitan), 通常采用组合策略:

* 单节点内(8 卡): 使用 TP, 利用 NVLink 高带宽;

* 跨节点间: 使用 PP, 减少节点间通信开销;

* 全局数据扩展: 叠加 DP/FSDP, 提升吞吐量.

### 3. 代码示例: Pipeline Parallel (PP) 在 PyTorch 中如何使用

从 PyTorch 2.2+ 开始, PyTorch 官方将原先的 PiPPy 库升级整合为原生的 `torch.distributed.pipelining` 模块, 这是目前 PyTorch 推荐的标准流水线并行接口.

下面是一个使用 PyTorch 原生 `torch.distributed.pipelining` 的完整、可运行代码示例(以 2 卡分布式训练、1F1B 调度为例):

```python
import os
import torch
import torch.nn as nn
import torch.distributed as dist
from torch.distributed.pipelining import PipelineStage, Schedule1F1B


# 1. 定义网络层结构(为展示清晰, 手动拆分为 Stage 0 和 Stage 1)
class Stage0Module(nn.Module):
    def __init__(self):
        super().__init__()
        self.layer1 = nn.Linear(64, 128)
        self.relu = nn.ReLU()

    def forward(self, x):
        return self.relu(self.layer1(x))


class Stage1Module(nn.Module):
    def __init__(self):
        super().__init__()
        self.layer2 = nn.Linear(128, 10)

    def forward(self, x):
        return self.layer2(x)


def run_pp():
    # 初始化分布式环境
    dist.init_process_group("nccl")
    rank = dist.get_rank()
    world_size = dist.get_world_size()
    assert world_size == 2, "本示例需要正好 2 个 GPU 进程运行"

    device = torch.device(f"cuda:{rank}")
    torch.cuda.set_device(device)

    # 2. 根据 Rank 划分并实例化当前卡对应的 Stage 模块
    if rank == 0:
        stage_module = Stage0Module().to(device)
    else:
        stage_module = Stage1Module().to(device)

    # 定义微批次 (Micro-batch) 维度
    micro_batch_size = 4
    num_microbatches = 4
    total_batch_size = micro_batch_size * num_microbatches  # 总 Batch Size = 16

    # 3. 构建 PipelineStage 对象
    # PipelineStage 会自动处理节点间发送 (Send) 和接收 (Recv) 的 P2P 通信逻辑
    example_input = torch.randn(micro_batch_size, 64, device=device)

    stage = PipelineStage(
        stage_module,
        stage_index=rank,
        num_stages=world_size,
        device=device,
        input_args=(
            (example_input,) if rank == 0 else None
        ),  # 仅 Stage 0 需要推导输入 shape
    )

    # 4. 创建 Pipeline 调度器 (此处使用 1F1B 调度策略)
    # 只有最后一个 Stage (Rank 1) 需要计算 Loss
    loss_fn = nn.MSELoss() if rank == world_size - 1 else None
    schedule = Schedule1F1B(stage, n_microbatches=num_microbatches, loss_fn=loss_fn)

    # Optimizer
    optimizer = torch.optim.AdamW(stage_module.parameters(), lr=1e-3)
    optimizer.zero_grad()

    # 5. 执行训练 Forward + Backward 步进
    if rank == 0:
        # 输入端 Stage: 传入完整 Batch 的 Input
        x = torch.randn(total_batch_size, 64, device=device)
        schedule.step(x)
    elif rank == world_size - 1:
        # 输出端 Stage: 传入 Target 标签用于计算 Loss
        target = torch.randn(total_batch_size, 10, device=device)
        # step() 会自动返回累加后的训练损失
        losses = []
        schedule.step(target=target, losses_output=losses)
        print(f"[Rank {rank}] Micro-batch Losses: {[l.item() for l in losses]}")
    else:
        # 中间 Stage (若 world_size > 2): 只需调用 step() 即可
        schedule.step()

    # 更新参数
    optimizer.step()

    print(f"[Rank {rank}] Pipeline 迭代成功完成!")
    dist.destroy_process_group()


if __name__ == "__main__":
    # 使用方式: 假设文件名为 pipelining_demo.py
    # 在命令行通过 torchrun 启动:
    # torchrun --nproc_per_node=2 pipelining_demo.py
    run_pp()

```

#### 代码重点解读:

1. `PipelineStage`: PyTorch 内部包装器, 负责捕捉输入/输出 Tensor 的形状, 并在内部构建基于 NCCL 的 `dist.send` 和 `dist.recv` 逻辑.

2. `Schedule1F1B`: PyTorch 的 1F1B 调度器, 自动将传入的 `total_batch_size` 切分为 `num_microbatches` 份, 并精确控制流水线的前向与反向执行交错顺序.

3. 前/后端数据注入: 首节点(Rank 0)输入 Raw Data, 尾节点(Rank N-1)输入 Target Label, 中间节点全自动流水传输, 开发者无需手动写复杂的分布式网络收发代码.

class TransformerBlock(nn.Module):

        self.linear1 = nn.Linear(dim, dim * 4)
        # model.layers[0].linear1.weight: torch.Size([256, 64])

        out = self.linear1(x)  # [Batch_Size, Seq_Len, Dim * 4]
        out = self.act(out)  # [Batch_Size, Seq_Len, Dim * 4]
        out = self.linear2(out)  # [Batch_Size, Seq_Len, Dim]
        return x + out  # 残差连接: [Batch_Size, Seq_Len, Dim]

### 二、各参数与配置详解

1. `vocab_size` (词表大小):
   * 对应模型能识别的独立 Token/词汇数量. Embedding 层矩阵为 `[vocab_size, dim]`, 最后的 Head 层权重为 `[vocab_size, dim]`.

2. `dim` (隐藏层/向量维度, 通常称为 $d_{model}$):
   * 每个 Token 在网络内部被编码表示的特征向量长度.

3. `num_layers` (层数):
   * TransformerBlock 堆叠的数量.

4. `batch_size` (批次大小):
   * 一次训练并行处理的样本(句子/文本块)数量.

5. `seq_len` (序列长度):
   * 每个样本包含的 Token 数量(文本上下文长度).

### 三、各层数据形状 (Shape) 全程追踪

设定参数为: `batch_size=2`, `seq_len=4`, `dim=64`, `vocab_size=100`.

| 步骤 / 层级              | 输入 Shape            | 输出 Shape                              | 说明 / 计算逻辑                                               |
| :----------------------- | :-------------------- | :-------------------------------------- | :------------------------------------------------------------ |
| 1. 输入 Token IDs        | -                     | `(2, 4)`                                | 离散的整数矩阵, 代表词表中 Token 的索引                       |
| 2. `self.embed`          | `(2, 4)`              | `(2, 4, 64)`                            | 查找表操作, 将每个索引映射为 64 维 Dense 向量                 |
| 3. Block 内 `linear1`    | `(2, 4, 64)`          | `(2, 4, 256)`                           | 升维: $64 \rightarrow 64 \times 4 = 256$                      |
| 4. Block 内 `act (GELU)` | `(2, 4, 256)`         | `(2, 4, 256)`                           | 逐元素激活函数, 维度保持不变                                  |
| 5. Block 内 `linear2`    | `(2, 4, 256)`         | `(2, 4, 64)`                            | 降维恢复: $256 \rightarrow 64$                                |
| 6. 残差加法 `x + out`    | `(2, 4, 64)`          | `(2, 4, 64)`                            | 与输入 `x` 逐元素相加(Residual Connection)                    |
| 7. `self.head` (分类头)  | `(2, 4, 64)`          | `(2, 4, 100)`                           | 线性映射到词表大小, 输出未归一化的 Logits                     |
| 8. 展开为 Loss 输入      | Logits: `(2, 4, 100)` | Logits: `(8, 100)` <br> Targets: `(8,)` | 将 Batch 和 Seq 维度合并为 $2 \times 4 = 8$ 个预测任务        |
| 9. `CrossEntropyLoss`    | `(8, 100)` 与 `(8,)`  | `()` (标量)                             | 对 8 个预测结果求 Softmax+ 交叉熵, 并取平均得到单个 Loss 标量 |

---

### 四、前向传播与反向传播详细过程解析

#### 1. 前向传播 (Forward Pass Process)

1. Embedding 查找: 输入 Token 索引 $(B, T)$, 通过矩阵查表获得相应的连续向量表示 $(B, T, D)$.

2. 残差前馈块 (FFN Blocks): 数据依次通过 2 个 `TransformerBlock`:
   * 扩展特征维度($\times 4$)以提供强非线性表达能力;
   * 使用 `GELU` 激活函数引入非线性;
   * 重新压缩回原始维度 $D$;
   * 残差连接 ($x + f(x)$): 直接把输入 $x$ 加到输出上. 这建立了一条无阻碍的信息高速公路, 可极大地缓解深层网络中的梯度消失问题.

3. 输出映射 (Head): 把最终的隐层特征投射回 `vocab_size` 空间, 得到对下一个词预测的未归一化概率得分(Logits).

4. 计算标量损失 (Loss Calculation): 利用交叉熵损失, 比较 Logits 与真实 Targets 的差距, 最终缩减为一个标量 `Loss`.

#### 2. 反向传播 (Backward Pass Process)

当执行 `loss.backward()` 时, PyTorch 的 Autograd 自动求导引擎 激活:

1. 梯度起点: 以标量 Loss 为起点, 令 $\frac{\partial Loss}{\partial Loss} = 1.0$.

2. 反向链式法则 (Chain Rule): 计算图从末端向前回溯, 依次求取各个算子的局部导数:
   * Head 层: 计算 Loss 对 `head.weight` 的梯度, 维度为 `[100, 64]`;
   * 残差块 (Residual Routing): 遇到加法节点 $x + f(x)$ 时, 梯度会无损地分流为两路: 一路直接沿主干路向更浅层传导, 另一路进入 `linear2 -> GELU -> linear1` 块计算局部梯度. 这保证了即时网络极深, 最前层的 Embedding 也能直接收到来自 Loss 的强梯度信号;
   * Embedding 层: 计算 Loss 对 `embed.weight` 的梯度, 维度为 `[100, 64]`.

3. 梯度积累与更新: 每个可训练参数 `param` 的 `.grad` 属性被填充. 随后执行 `optimizer.step()`, AdamW 优化器利用保存的动量和当前梯度, 按公式更新模型参数:
   $$W \leftarrow W - \eta \cdot \text{AdamW}(\nabla_W Loss)$$

---

### 五、资源回收说明 (Resource Cleanup)

在 LLM 训练中, 内存/显存泄漏是常见问题. 脚本最后完成了两步清理:
1. `del` 显式解除引用: 删除了 `model`、`optimizer`、中间张量(`logits`, `loss` 等)在当前作用域的引用, 使得这些对象变为"不可达"状态.
2. `gc.collect()` 显式垃圾回收: 强制 Python 垃圾回收器立即清理无用对象, 释放内存空间. 如果是在 CUDA(GPU)上运行, 还会补充调用 `torch.cuda.empty_cache()` 来释放 PyTorch 缓存池占用的显存.

### 一、从纯文本到张量 (Text to Tensor) 的完整流程

工业界最标准的做法是使用 Tokenizer(分词器, 如 Byte-Pair Encoding / BPE 算法). 目前主流的工具库是 Hugging Face 的 `transformers` 或 OpenAI 的 `tiktoken`.

下面以 Hugging Face `transformers` 为例展示转换过程:

```python
import torch
from transformers import AutoTokenizer

# 1. 加载预训练分词器 (以 gpt2 为例, 也可以是 llama, Qwen 等)
tokenizer = AutoTokenizer.from_pretrained("gpt2")

# 设置填充 token(GPT-2 默认没有 pad_token, 通常指定为 eos_token)
if tokenizer.pad_token is None:
    tokenizer.pad_token = tokenizer.eos_token

# 2. 原始纯文本列表
raw_texts = [
    "I love PyTorch and Deep Learning.",  # 较短的文本
    "Large language models have revolutionized natural language processing and artificial intelligence.",  # 较长的文本
]

# 3. 超参数定义
BATCH_SIZE = len(raw_texts)  # 2
SEQ_LEN = 8  # 设定固定序列长度为 8

# 4. 执行 Tokenization(包含分词、ID映射、截断与填充)
inputs = tokenizer(
    raw_texts,
    padding="max_length",  # 不够 SEQ_LEN 的进行填充 (Padding)
    truncation=True,  # 超过 SEQ_LEN 的进行截断 (Truncation)
    max_length=SEQ_LEN,  # 目标序列长度
    return_tensors="pt",  # 直接返回 PyTorch Tensor
)

# 5. 提取 input_ids
input_ids = inputs["input_ids"]

print("=== 转换结果 ===")
print("Generated Tensor Shape:", input_ids.shape)  # 输出: torch.Size([2, 8])
print("Tensor Matrix:\n", input_ids)

# 6. 解码验证(看看模型实际看到的内容)
for i, token_ids in enumerate(input_ids):
    decoded_text = tokenizer.decode(token_ids)
    print(f"Sample {i+1} decoded: '{decoded_text}'")
```

#### 转换逻辑分解:

1. 分词与映射: 字符串被切分为词元(Tokens), 并查表映射为整数 ID(例如 `"I"` $\rightarrow$ `40`).
2. 截断(Truncation): 第二句话很长, 被强行裁切保留前 8 个 Token.
3. 填充(Padding): 第一句话较短(只有 7 个 Token), 尾部被补上了一个特殊占位符 `<|endoftext|>`(ID 为 `50256`), 使得每行长度强行对齐到 8.

### 二、两个关键参数的具体含义

在单次训练或推理步骤中, 模型实际处理的总 Token 数等于:
$$\text{Total Tokens} = \text{BATCH\_SIZE} \times \text{SEQ\_LEN}$$

#### 1. `SEQ_LEN` (Sequence Length / 上下文长度 / 窗口大小)

* 含义: 单条文本被送入模型时的 Token 数量. 它代表了模型单次能"看见"的上下文视野(Context Window).
* 物理意义: 自注意力机制(Self-Attention)的计算复杂度与 `SEQ_LEN` 呈二次方关系 $O(\text{SEQ\_LEN}^2)$(若未应用 FlashAttention 等优化). `SEQ_LEN` 越大, 模型的长期记忆和长文理解能力越强, 但显存与计算开销呈暴增趋势.

#### 2. `BATCH_SIZE` (Batch Size / 批次大小)

* 含义: 一次前向+反向传播中, 同时并行处理的文本样本条数.
* 物理意义: 大模型训练通常利用 GPU 的大规模并行计算能力. `BATCH_SIZE` 越大, 硬件利用率(吞吐量/Throughput)越高, 梯度的方差越小, 训练越稳定; 但它与显存消耗呈线性关系 $O(\text{BATCH\_SIZE})$.

---

### 三、在真实环境中, 如何确定这两个参数的值?

在大模型预训练(Pre-training)、微调(SFT)和推理(Inference)中, 参数设定遵循不同的设计法则:

#### 1. 如何确定 `SEQ_LEN`?

| 决策因素            | 设定逻辑与常见值                                                                                                                                                                                         |
| :------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. 模型架构设计上限 | 由位置编码(Positional Encoding)决定. 例如: 早期 LLaMA 设定为 2048/4096; LLaMA-3 扩展到 8192; GPT-4 扩展到 128k. 输入的 `SEQ_LEN` 绝不能超过模型训练时支持的最大位置上限(除非使用了 RoPE 缩放等外推技术). |
| 2. 业务任务场景     | 短文本对话/分类: `SEQ_LEN` 设为 512 ~ 2048 即可. <br> 长文档摘要/代码分析/长对话: 通常需要 8192、32768 甚至更高.                                                                                         |
| 3. 硬件显存瓶颈     | Attention 矩阵的大小是 `[BATCH_SIZE, NUM_HEADS, SEQ_LEN, SEQ_LEN]`. 如果显存爆了(OOM), 降低 `SEQ_LEN` 是最直接的手段.                                                                                    |

#### 2. 如何确定 `BATCH_SIZE`?

在实际工程中, `BATCH_SIZE` 分为 Micro Batch Size(单卡/单次批大小) 和 Global Batch Size(全局总批大小).

$$\text{Global Batch Size} = \text{Micro Batch Size} \times \text{并行 GPU 数量} \times \text{梯度累加步数 (Gradient Accumulation Steps)}$$

确定策略如下:

1. 单卡 Micro Batch Size:
   * 准则: 在显存允许的范围内(不发生 OOM), 尽量把显卡吃满.
   * 常见做法: 通常设为 $2^n$(如 1, 2, 4, 8, 16), 符合 GPU Tensor Core 的内存对齐逻辑, 计算效率最高. 如果设为 `Micro Batch Size = 2` 就爆显存, 可以使用 激活重算 (Activation Checkpointing) 或 FlashAttention 优化, 而不是盲目降到 1.

2. 全局 Global Batch Size(主要看训练收敛性):
   * Pre-training(预训练): 追求海量数据吞吐, 全局 Batch 通常极其庞大(例如以 Token 数 计算, 单步全局处理 100 万到 400 万 Tokens, 如 $B_{global} \times L = 4M$).
   * SFT(指令微调): 全局 Batch 通常较小(例如 64, 128 或 256 条样本), 过大的 Batch Size 会导致模型拟合能力下降(缺乏梯度的随机噪声).

---

### 总结给研究人员的配置口诀:

1. 先定 `SEQ_LEN`: 根据你的业务数据分布(取 95% 文本能完整覆盖的长度)和模型的最大位置编码上限来确定.
2. 再凑 `BATCH_SIZE`:
   * 测出单张 GPU 显存能承受的最大 `Micro Batch Size`;
   * 若理想的 `Global Batch Size` 较大, 通过 梯度累加(Gradient Accumulation) 来达到目标, 从而解耦显存限制与数学收敛需求.

class SimpleLLM(nn.Module):
    def __init__(self, vocab_size=10000, dim=2048, num_layers=4):
        super().__init__()
        self.embed = nn.Embedding(vocab_size, dim)

我们基于 PyTorch 官方推荐的 `torch.distributed.pipelining` 方案(PyTorch 2.2+ 原生支持), 将你的 `SimpleLLM` 拆分成 8 个阶段(Stage), 分别加载到 8 张 GPU 上.

### 1. 完整训练脚本(`train_pp_8gpu.py`)

请将以下代码保存为文件 `train_pp_8gpu.py`:

```python
import os
import torch
import torch.nn as nn
import torch.distributed as dist
from torch.distributed.pipelining import PipelineStage, Schedule1F1B


# ================= 1. 基础模型组件定义 (保持你的源码不变) =================
class TransformerBlock(nn.Module):
    def __init__(self, dim: int):
        super().__init__()
        self.linear1 = nn.Linear(dim, dim * 4)
        self.act = nn.GELU()
        self.linear2 = nn.Linear(dim * 4, dim)

    def forward(self, x):
        return x + self.linear2(self.act(self.linear1(x)))


# ================= 2. 针对 PP 改造的 Stage 包装模块 =================
class PipelineLLMStage(nn.Module):
    """
    根据进程的 Rank, 将原本的 SimpleLLM 划分为 8 个 Stage:
    - Rank 0: Embed + 1个 TransformerBlock
    - Rank 1~6: 1个 TransformerBlock
    - Rank 7: 1个 TransformerBlock + Output Head
    """

    def __init__(
        self,
        stage_idx: int,
        total_stages: int,
        vocab_size=10000,
        dim=2048,
        layers_per_stage=1,
    ):
        super().__init__()
        self.stage_idx = stage_idx
        self.total_stages = total_stages

        # Stage 0 包含 Embedding
        if stage_idx == 0:
            self.embed = nn.Embedding(vocab_size, dim)
        else:
            self.embed = None

        # 每个 Stage 包含分配给它的 Transformer 块
        self.blocks = nn.ModuleList(
            [TransformerBlock(dim) for _ in range(layers_per_stage)]
        )

        # 最后一个 Stage 包含 Head 线性层
        if stage_idx == total_stages - 1:
            self.head = nn.Linear(dim, vocab_size)
        else:
            self.head = None

    def forward(self, x):
        # 如果是首阶段, 输入为 Token IDs (Shape: [B, S]), 先过 Embedding
        if self.embed is not None:
            x = self.embed(x)  # -> Shape: [B, S, D]

        # 依次经过当前 Stage 的 TransformerBlock
        for block in self.blocks:
            x = block(x)

        # 如果是末阶段, 计算 Logits (Shape: [B, S, V])
        if self.head is not None:
            x = self.head(x)

        return x


# 自定义损失函数, 用于最后一个 Stage 节点计算 CrossEntropy
def token_cross_entropy_loss(outputs, targets):
    # outputs: [B, S, Vocab_size], targets: [B, S]
    return nn.functional.cross_entropy(
        outputs.view(-1, outputs.size(-1)), targets.view(-1)
    )


# ================= 3. 主训练流程 =================
def main():
    # A. 分布式环境初始化
    dist.init_process_group(backend="nccl")

    local_rank = int(os.environ["LOCAL_RANK"])
    world_size = int(os.environ["WORLD_SIZE"])
    assert world_size == 8, f"本脚本配置为 8 卡 PP 运行, 当前卡数为 {world_size}"

    device = torch.device(f"cuda:{local_rank}")
    torch.cuda.set_device(device)

    # B. 超参数设定
    vocab_size = 10000
    dim = 2048
    seq_len = 128

    # 模拟输入参数: Batch 切分为 4 个 Micro-batches
    micro_batch_size = 2
    n_microbatches = 4
    total_batch_size = micro_batch_size * n_microbatches  # 8

    # C. 实例化当前 GPU 对应的 Stage 模块
    stage_module = PipelineLLMStage(
        stage_idx=local_rank,
        total_stages=world_size,
        vocab_size=vocab_size,
        dim=dim,
        layers_per_stage=1,  # 8 卡, 每卡 1 层, 总计 8 层 Transformer Block
    ).to(device)

    # D. 创建 PipelineStage
    # 只需要给 Rank 0 传入用于形状推导的示例输入
    example_input = (
        torch.randint(0, vocab_size, (micro_batch_size, seq_len), device=device)
        if local_rank == 0
        else None
    )

    stage = PipelineStage(
        stage_module,
        stage_index=local_rank,
        num_stages=world_size,
        device=device,
        input_args=(example_input,) if local_rank == 0 else None,
    )

    # E. 配置 1F1B 调度器
    loss_fn = token_cross_entropy_loss if local_rank == world_size - 1 else None
    schedule = Schedule1F1B(stage, n_microbatches=n_microbatches, loss_fn=loss_fn)

    # 优化器 (每个卡只优化属于它当前 Stage 的参数)
    optimizer = torch.optim.AdamW(stage_module.parameters(), lr=1e-4)

    # F. 模拟 5 个 Step 的训练循环
    for step in range(1, 6):
        optimizer.zero_grad()

        # 生成本 Step 的随机数据
        if local_rank == 0:
            # 首卡生成输入 Input Tokens [B, S]
            inputs = torch.randint(
                0, vocab_size, (total_batch_size, seq_len), device=device
            )
            schedule.step(inputs)
        elif local_rank == world_size - 1:
            # 尾卡生成目标 Target Tokens [B, S]
            targets = torch.randint(
                0, vocab_size, (total_batch_size, seq_len), device=device
            )
            losses = []
            schedule.step(target=targets, losses_output=losses)
            avg_loss = sum([l.item() for l in losses]) / len(losses)
            print(f"[Step {step}] Loss: {avg_loss:.4f}")
        else:
            # 中间卡不需要直接输入/输出数据, 全自动通过 P2P 传输
            schedule.step()

        optimizer.step()

    # ================= 4. 模型保存 (Save Checkpoint) =================
    ckpt_dir = "./checkpoints_pp"
    if local_rank == 0:
        os.makedirs(ckpt_dir, exist_ok=True)

    dist.barrier()  # 确保目录已创建

    # 在 PP 模式下, 推荐每个 Rank 保存属于本 Stage 的权重字典 (State Dict)
    ckpt_path = os.path.join(ckpt_dir, f"model_stage_{local_rank}.pt")
    torch.save(stage_module.state_dict(), ckpt_path)
    print(f"[Rank {local_rank}] 成功保存当前 Stage 权重至: {ckpt_path}")

    # ================= 5. 资源回收 (Cleanup) =================
    # 同步所有 GPU 进程, 确保写文件等操作已全部完毕
    dist.barrier()

    # 销毁分布式通信进程组
    dist.destroy_process_group()

    # 显式清理 GPU 缓存
    torch.cuda.empty_cache()
    if local_rank == 0:
        print("\n所有训练任务已完成, 分布式进程组已销毁, GPU 显存已释放.")


if __name__ == "__main__":
    main()

```

### 3. 脚本关键设计细节解析

1. Stage 拆分逻辑 (`PipelineLLMStage`):

   * 原本你的 `SimpleLLM` 内部有 `embed`、`layers` 和 `head`.

   * 我们将其逻辑打碎: `Rank 0` 持有 `embed` 和第 1 个 Transformer 块; `Rank 1~6` 各自持有 1 个 Transformer 块; `Rank 7` 持有最后一个 Transformer 块以及 `head`.

2. 数据流通信(Automatic P2P):

   * `Schedule1F1B` 会自动在 Rank 0 传递 `Activation` 给 Rank 1, Rank 1 给 Rank 2 ... 直到 Rank 7.

   * 反向传播时, 梯度从 Rank 7 逆向传递回 Rank 0, 使用者无需编写任何 `dist.send` 或 `dist.recv`.

3. 模型 Checkpoint 保存:

   * 流水线并行每个卡上保存的是模型的分片参数. 脚本将保存 8 个文件: `model_stage_0.pt` 到 `model_stage_7.pt`. 加载推理时, 只需把各 Stage 文件读入并重新拼装即可(这也是主流大模型训练如 Megatron-LM 的标准实践).

4. 资源安全回收:

   * 通过 `dist.barrier()` 确保 8 个卡都写完磁盘后, 调用 `dist.destroy_process_group()` 优雅关闭 NCCL 通信句柄, 并调用 `torch.cuda.empty_cache()` 归还显存.

### 1. 完整训练脚本(`train_pp_multi_node.py`)

请在两台机器的相同路径下保存一份完全相同的 `train_pp_multi_node.py` 文件:

```python
import os
import torch
import torch.nn as nn
import torch.distributed as dist
from torch.distributed.pipelining import PipelineStage, Schedule1F1B


# ================= 1. 基础模型组件定义 =================
class TransformerBlock(nn.Module):
    def __init__(self, dim: int):
        super().__init__()
        self.linear1 = nn.Linear(dim, dim * 4)
        self.act = nn.GELU()
        self.linear2 = nn.Linear(dim * 4, dim)

    def forward(self, x):
        return x + self.linear2(self.act(self.linear1(x)))


# ================= 2. 针对多机多卡 (16 Stages) 的 Stage 模块 =================
class PipelineLLMStage(nn.Module):
    """
    根据全局进程的 global_rank, 将 SimpleLLM 划分为 16 个 Stage:
    - Global Rank 0 (Node 0, GPU 0): Embed + 1个 TransformerBlock
    - Global Rank 1~14: 1个 TransformerBlock
    - Global Rank 15 (Node 1, GPU 7): 1个 TransformerBlock + Output Head
    """

    def __init__(
        self,
        stage_idx: int,
        total_stages: int,
        vocab_size=10000,
        dim=2048,
        layers_per_stage=1,
    ):
        super().__init__()
        self.stage_idx = stage_idx
        self.total_stages = total_stages

        # 全局 Rank 0 包含 Embedding
        if stage_idx == 0:
            self.embed = nn.Embedding(vocab_size, dim)
        else:
            self.embed = None

        # 每个 Stage 包含指定数量的 TransformerBlock
        self.blocks = nn.ModuleList(
            [TransformerBlock(dim) for _ in range(layers_per_stage)]
        )

        # 全局最后一个 Stage (Rank 15) 包含 Output Head
        if stage_idx == total_stages - 1:
            self.head = nn.Linear(dim, vocab_size)
        else:
            self.head = None

    def forward(self, x):
        # 如果是首阶段 (Rank 0), 输入为 Token IDs [B, S]
        if self.embed is not None:
            x = self.embed(x)  # -> [B, S, D]

        for block in self.blocks:
            x = block(x)

        # 如果是末阶段 (Rank 15), 计算 Logits [B, S, V]
        if self.head is not None:
            x = self.head(x)

        return x


def token_cross_entropy_loss(outputs, targets):
    return nn.functional.cross_entropy(
        outputs.view(-1, outputs.size(-1)), targets.view(-1)
    )


# ================= 3. 主训练流程 =================
def main():
    # A. 分布式通信初始化
    dist.init_process_group(backend="nccl")

    global_rank = dist.get_rank()  # 全局 Rank: 0 ~ 15
    world_size = dist.get_world_size()  # 总卡数: 16
    local_rank = int(os.environ["LOCAL_RANK"])  # 单机内部 GPU 卡号: 0 ~ 7

    assert (
        world_size == 16
    ), f"本脚本配置为 2 台机器共 16 卡训练, 当前检测到 world_size={world_size}"

    # 绑卡必须使用 local_rank (0~7)
    device = torch.device(f"cuda:{local_rank}")
    torch.cuda.set_device(device)

    # B. 模型超参数
    vocab_size = 10000
    dim = 2048
    seq_len = 128

    micro_batch_size = 2
    n_microbatches = 4
    total_batch_size = micro_batch_size * n_microbatches  # 8

    # C. 实例化当前 GPU 对应的 Stage (基于 global_rank 切分)
    stage_module = PipelineLLMStage(
        stage_idx=global_rank,
        total_stages=world_size,
        vocab_size=vocab_size,
        dim=dim,
        layers_per_stage=1,  # 16 卡, 每卡 1 层, 总计 16 层 TransformerBlock
    ).to(device)

    # D. 构建 PipelineStage (通过 global_rank 指定处于流水线的第几段)
    example_input = (
        torch.randint(0, vocab_size, (micro_batch_size, seq_len), device=device)
        if global_rank == 0
        else None
    )

    stage = PipelineStage(
        stage_module,
        stage_index=global_rank,
        num_stages=world_size,
        device=device,
        input_args=(example_input,) if global_rank == 0 else None,
    )

    # E. 配置 1F1B 调度器
    loss_fn = token_cross_entropy_loss if global_rank == world_size - 1 else None
    schedule = Schedule1F1B(stage, n_microbatches=n_microbatches, loss_fn=loss_fn)

    optimizer = torch.optim.AdamW(stage_module.parameters(), lr=1e-4)

    # F. 训练循环 (跨节点传输由 NCCL 自动处理, 比如 Stage 7(节点0) -> Stage 8(节点1))
    for step in range(1, 6):
        optimizer.zero_grad()

        if global_rank == 0:
            # Node 0 的 GPU 0: 生成原始输入 Inputs [B, S]
            inputs = torch.randint(
                0, vocab_size, (total_batch_size, seq_len), device=device
            )
            schedule.step(inputs)
        elif global_rank == world_size - 1:
            # Node 1 的 GPU 7: 生成目标标签 Targets [B, S], 计算 Loss
            targets = torch.randint(
                0, vocab_size, (total_batch_size, seq_len), device=device
            )
            losses = []
            schedule.step(target=targets, losses_output=losses)
            avg_loss = sum([l.item() for l in losses]) / len(losses)
            print(
                f"[Step {step}] Loss (Calculated on Node 1 / Rank 15): {avg_loss:.4f}"
            )
        else:
            # 中间所有卡: 自动接收上游 Stage 数据, 计算后发给下游 Stage
            schedule.step()

        optimizer.step()

    # ================= 4. 模型保存 (Save Checkpoint) =================
    ckpt_dir = "./checkpoints_pp_multi_node"
    os.makedirs(ckpt_dir, exist_ok=True)

    dist.barrier()  # 跨节点同步, 确保所有卡目录建立完成

    # 每个 GPU 保存属于本 Stage 的权重字典
    ckpt_path = os.path.join(ckpt_dir, f"model_stage_{global_rank}.pt")
    torch.save(stage_module.state_dict(), ckpt_path)
    print(
        f"[Global Rank {global_rank} | Local Rank {local_rank}] 保存 Checkpoint 至: {ckpt_path}"
    )

    # ================= 5. 资源回收 (Cleanup) =================
    dist.barrier()  # 等待所有机器的所有节点写盘完成

    dist.destroy_process_group()  # 关闭跨节点 NCCL 套接字通信
    torch.cuda.empty_cache()  # 清空 GPU 显存缓存

    if global_rank == 0:
        print(
            "\n[Node 0 / Master] 多机多卡训练完成, 通信进程组已销毁, GPU 显存已完全释放."
        )


if __name__ == "__main__":
    main()

```

### 3. 多机多卡的核心技术要点说明

1. `torchrun` 多机参数解析:

   * `--nnodes=2`: 告诉 PyTorch 一共有 2 台物理机器参与训练.

   * `--nproc_per_node=8`: 每台机器有 8 张 GPU, 总卡数为 $2 \times 8 = 16$ 卡.

   * `--node_rank`: 物理机的编号. 主节点设为 `0`, 从节点设为 `1`.

   * `--master_addr` 和 `--master_port`: 所有机器依靠这个主节点 IP 和端口进行分布式握手.

2. 跨节点 P2P 通信与跨卡边界:

   * 在这个 16 卡流水线中, `Stage 7` 位于 Node 0 的 GPU 7, `Stage 8` 位于 Node 1 的 GPU 0.

   * 当训练进行到边界时, PyTorch 的 `PipelineStage` 会自动识别出这两个卡属于不同物理机, 并通过网卡(TCP 或 InfiniBand/RoCE)将前向激活值(Activation)从 Node 0 发送到 Node 1; 反向传播时将梯度从 Node 1 发送回 Node 0.

3. 模型保存与共享存储:

   * 如果有共享文件系统(如 NFS / Lustre): Node 0 和 Node 1 会将 16 个文件(`model_stage_0.pt` ~ `model_stage_15.pt`)统一保存在同个挂载路径下.

   * 如果没有共享文件系统(本地独立硬盘): Node 0 的本地磁盘会存有 `model_stage_0.pt` 到 `model_stage_7.pt`; Node 1 的本地磁盘会存有 `model_stage_8.pt` 到 `model_stage_15.pt`.

### 3. 代码运行与设计流程解析

1. 底层通信解耦:

   * `torchrun` 会自动在后台拉起 8 个独立的 Python 进程, 并自动传入环境变量(如 `RANK`, `LOCAL_RANK`, `WORLD_SIZE`, `MASTER_ADDR`, `MASTER_PORT`).

   * 代码内部调用 `dist.init_process_group("nccl")` 读取上述环境变量, 完成 GPU 间通信环境的建立.

2. 流水线调度 (`Schedule1F1B`):

   * 调度器会自动将总 Batch(Size=8)划分成 4 个 Micro-batch(每个 Size=2).

   * `Rank 0` 到 `Rank 7` 会以 1F1B(一次前向, 一次反向)的节奏高效交替运行, 避免 GPU 空闲等待.

3. 分片保存与资源回收:

   * 保存: 8 张卡会分别在 `./checkpoints_pp_single_node/` 目录下生成 `model_stage_0.pt` 至 `model_stage_7.pt`.

   * 回收: 通过 `dist.barrier()` 进行分布式栅栏同步, 确保没有任何卡提前挂断导致死锁, 最后调用 `dist.destroy_process_group()` 与 `torch.cuda.empty_cache()` 完成资源完全释放.

### 1. 完整训练脚本(`train_pp_multi_node.py`)

请将以下代码保存为 `train_pp_multi_node.py`, 并同步放置在两台机器相同的目录路径下:

```python
import os
import torch
import torch.nn as nn
import torch.distributed as dist
from torch.distributed.pipelining import PipelineStage, Schedule1F1B


# ================= 1. 基础模型组件 (保持你的源码定义) =================
class TransformerBlock(nn.Module):
    def __init__(self, dim: int):
        super().__init__()
        self.linear1 = nn.Linear(dim, dim * 4)
        self.act = nn.GELU()
        self.linear2 = nn.Linear(dim * 4, dim)

    def forward(self, x):
        return x + self.linear2(self.act(self.linear1(x)))


# ================= 2. 针对多机 16 个 Stage 的 Pipeline 包装模块 =================
class PipelineLLMStage(nn.Module):
    """
    根据全局进程的 global_rank, 将 SimpleLLM 划分为 16 个 Stage:
    - Global Rank 0 (Node 0, GPU 0): Embed + 1个 TransformerBlock
    - Global Rank 1~14: 1个 TransformerBlock
    - Global Rank 15 (Node 1, GPU 7): 1个 TransformerBlock + Output Head
    """

    def __init__(
        self,
        stage_idx: int,
        total_stages: int,
        vocab_size=10000,
        dim=2048,
        layers_per_stage=1,
    ):
        super().__init__()
        self.stage_idx = stage_idx
        self.total_stages = total_stages

        # 仅全局 Stage 0 包含 Embedding 层
        if stage_idx == 0:
            self.embed = nn.Embedding(vocab_size, dim)
        else:
            self.embed = None

        # 每个 Stage 分配 1 个 TransformerBlock
        self.blocks = nn.ModuleList(
            [TransformerBlock(dim) for _ in range(layers_per_stage)]
        )

        # 仅全局最后一个 Stage (Stage 15) 包含 Linear Head 层
        if stage_idx == total_stages - 1:
            self.head = nn.Linear(dim, vocab_size)
        else:
            self.head = None

    def forward(self, x):
        # 如果是全局首阶段, 输入为 Token IDs [B, S], 先做 Embedding
        if self.embed is not None:
            x = self.embed(x)  # -> [B, S, D]

        for block in self.blocks:
            x = block(x)

        # 如果是全局末阶段, 计算 Logits [B, S, Vocab_size]
        if self.head is not None:
            x = self.head(x)

        return x


# 自定义 Loss 函数: 在末端 Stage 节点计算交叉熵
def token_cross_entropy_loss(outputs, targets):
    return nn.functional.cross_entropy(
        outputs.view(-1, outputs.size(-1)), targets.view(-1)
    )


# ================= 3. 主训练流程 =================
def main():
    # A. 初始化通信组 (torchrun 多机启动时会自动传递关联信息)
    dist.init_process_group(backend="nccl")

    global_rank = dist.get_rank()  # 全局卡号: 0 ~ 15
    world_size = dist.get_world_size()  # 总卡数: 16
    local_rank = int(os.environ["LOCAL_RANK"])  # 单机内部 GPU ID: 0 ~ 7

    assert (
        world_size == 16
    ), f"本脚本针对 2 台机器共 16 卡训练设计, 当前检测到 world_size={world_size}"

    # 单机绑卡必须使用 local_rank (0 ~ 7)
    device = torch.device(f"cuda:{local_rank}")
    torch.cuda.set_device(device)

    # B. 超参数定义
    vocab_size = 10000
    dim = 2048
    seq_len = 128

    # 微批次 (Micro-batch) 设置
    micro_batch_size = 2
    n_microbatches = 4
    total_batch_size = micro_batch_size * n_microbatches  # 相当于全局 Batch Size = 8

    # C. 实例化当前 GPU 对应的 Stage 模块 (按 global_rank 划分 16 个阶段)
    stage_module = PipelineLLMStage(
        stage_idx=global_rank,
        total_stages=world_size,
        vocab_size=vocab_size,
        dim=dim,
        layers_per_stage=1,  # 16 卡每卡 1 层, 构成 16 层 Transformer 的大模型
    ).to(device)

    # D. 构建 PipelineStage
    example_input = (
        torch.randint(0, vocab_size, (micro_batch_size, seq_len), device=device)
        if global_rank == 0
        else None
    )

    stage = PipelineStage(
        stage_module,
        stage_index=global_rank,
        num_stages=world_size,
        device=device,
        input_args=(example_input,) if global_rank == 0 else None,
    )

    # E. 配置 1F1B 流水线调度器
    loss_fn = token_cross_entropy_loss if global_rank == world_size - 1 else None
    schedule = Schedule1F1B(stage, n_microbatches=n_microbatches, loss_fn=loss_fn)

    # 优化器 (各卡只优化属于本 Stage 的参数)
    optimizer = torch.optim.AdamW(stage_module.parameters(), lr=1e-4)

    # F. 执行 5 个 Step 的模拟训练
    for step in range(1, 6):
        optimizer.zero_grad()

        if global_rank == 0:
            # Node 0 / GPU 0: 生成原始输入 Inputs [B, S]
            inputs = torch.randint(
                0, vocab_size, (total_batch_size, seq_len), device=device
            )
            schedule.step(inputs)
        elif global_rank == world_size - 1:
            # Node 1 / GPU 7 (Stage 15): 生成 Target 标签并计算 Loss
            targets = torch.randint(
                0, vocab_size, (total_batch_size, seq_len), device=device
            )
            losses = []
            schedule.step(target=targets, losses_output=losses)
            avg_loss = sum([l.item() for l in losses]) / len(losses)
            print(f"[Step {step}] Loss (Calculated on Node 1 / GPU 7): {avg_loss:.4f}")
        else:
            # 中间所有卡: 自动完成节点内 / 跨节点的 P2P 接收、计算与转发
            schedule.step()

        optimizer.step()

    # ================= 4. 模型保存 (Save Checkpoint) =================
    ckpt_dir = "./checkpoints_pp_multi_node"
    os.makedirs(ckpt_dir, exist_ok=True)

    # 跨节点全局栅栏同步, 保证所有机器的保存目录均准备就绪
    dist.barrier()

    # 每张卡保存属于本 Stage 的权重字典
    ckpt_path = os.path.join(ckpt_dir, f"model_stage_{global_rank}.pt")
    torch.save(stage_module.state_dict(), ckpt_path)
    print(
        f"[Global Rank {global_rank} | Local Rank {local_rank}] 成功保存 Stage 权重分片至: {ckpt_path}"
    )

    # ================= 5. 资源回收 (Cleanup) =================
    # 全局栅栏同步, 等待两台机器的所有 16 张卡完全写盘完毕
    dist.barrier()

    # 销毁跨节点的 NCCL 通信进程组
    dist.destroy_process_group()

    # 清空 GPU 显存缓存
    torch.cuda.empty_cache()

    if global_rank == 0:
        print(
            "\n[Node 0 / Master] 多机 16 卡 PP 训练全部完成! 通信组已销毁, GPU 显存已释放."
        )


if __name__ == "__main__":
    main()

```

### 2. 如何使用 `torchrun` 执行多机训练?

假设两台机器的局域网配置如下:

* Node 0 (主节点): IP 地址为 `192.168.1.100`, `node_rank=0`

* Node 1 (从节点): IP 地址为 `192.168.1.101`, `node_rank=1`

* 通信端口: 选定 `29500`(需确保两台机器之间防火墙允许此端口通信)

#### 步骤 1: 在 Node 0 (主节点) 上启动

打开 Node 0 的终端, 运行以下命令:

```bash
torchrun \
    --nnodes=2 \
    --nproc_per_node=8 \
    --node_rank=0 \
    --master_addr=192.168.1.100 \
    --master_port=29500 \
    train_pp_multi_node.py
```

#### 步骤 2: 在 Node 1 (从节点) 上启动

打开 Node 1 的终端, 运行以下命令(注意修改 `--node_rank=1`):

```bash
torchrun \
    --nnodes=2 \
    --nproc_per_node=8 \
    --node_rank=1 \
    --master_addr=192.168.1.100 \
    --master_port=29500 \
    train_pp_multi_node.py
```

### 3. 多机多卡关键要点说明

1. `global_rank` 与 `local_rank` 的职责分离:

   * `local_rank`(0~7): 仅用于 `torch.cuda.set_device(local_rank)` 绑定本台机器上的具体哪张显卡.

   * `global_rank`(0~15): 用于构建流水线通信图. PyTorch 据此判断 `Stage 0~7` 位于 Node 0, `Stage 8~15` 位于 Node 1.

2. 跨节点(Inter-node)无缝接驳:

   * 在 Stage 7 到 Stage 8 的切换时, `PipelineStage` 会自动识别出这两个卡位于不同的 `master_addr` 节点上, 并自动使用 NCCL 库通过网络套接字(如 InfiniBand / RoCE / TCP)发送激活值与梯度, 开发者不需要写任何网络发送代码.

3. 模型 Checkpoint 存储:

   * 如果两台机器挂载了共享存储(如 NFS/Lustre), 则 `./checkpoints_pp_multi_node/` 下会自动收集完整的 16 个 `model_stage_0.pt` ~ `model_stage_15.pt` 文件.

   * 如果是本地硬盘, Node 0 会存有 Stage 0~7, Node 1 会存有 Stage 8~15. 加载模型时合并这 16 个 State Dict 即可复原完整权重.
