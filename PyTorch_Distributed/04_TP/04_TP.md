### 1. 什么是 Tensor Parallelism (TP)? 具体含义是什么?

#### 核心定义

张量并行(Tensor Parallelism) 是一种层内(Intra-Layer)的分布式并行技术. 与数据并行(Data Parallel, 切分 Batch Dimension)和流水线并行(Pipeline Parallel, 按 Layer 切分网络层)不同, TP 将单个 Transformer 层内部的大型张量(如权重矩阵 $W$ 和激活值 $X$)切分到多个 GPU 上同时进行计算.

#### 数学与逻辑原理(以矩阵乘法 $Y = XW$ 为例)

TP 最早由 NVIDIA 在 Megatron-LM 论文中提出. 核心思路是将线性层(Linear Layer)的矩阵乘法拆分为以下两种基本模式:

1. 列并行(Column Parallel Linear):

   * 将权重矩阵 $W$ 按列切分为 $W_1, W_2, \dots, W_k$.

   * 输入 $X$ 被广播(Broadcast)到所有 GPU.

   * 每个 GPU 独立计算: $Y_i = X W_i$.

   * 结果 $Y = [Y_1, Y_2, \dots, Y_k]$, 按列拼接(Concat), 或保持切分状态直接传给下一层.

2. 行并行(Row Parallel Linear):

   * 输入张量按列切分为 $X_1, X_2$, 权重矩阵 $W$ 按行切分为 $W_1, W_2$.

   * 每个 GPU 计算局部结果: $Z_i = X_i W_i$.

   * 最终输出需要通过 All-Reduce (Sum) 通信原语聚合: $Y = Z_1 + Z_2 = X_1 W_1 + X_2 W_2$.

#### 在 Transformer 中的高效组合

为了减少 GPU 间高昂的通信开销, Megatron-LM 设计了极为巧秒的匹配:

* MLP 模块: 第一层 Linear 做列并行 $\rightarrow$ 激活函数(无通信) $\rightarrow$ 第二层 Linear 做行并行.

  * 通信开销: 整个 MLP 模块仅在第二层结束时需要 1 次 All-Reduce!

* Attention 模块: $Q, K, V$ 投影做列并行(按注意力头 Head 切分) $\rightarrow$ 局部自注意力计算 $\rightarrow$ Out Projection 做行并行.

  * 通信开销: 整个 Attention 模块仅需要 1 次 All-Reduce!

### 2. 为什么需要 Tensor Parallelism (TP)?

在大模型训练和推理中, TP 解决了以下几个核心痛点:

#### 1 单层权重/激活值超出单卡显存(Memory Limit)

在 70B 甚至 405B 参数的模型中, 单个 Linear 层的权重矩阵可能高达数十 GB.

* 流水线并行 (PP) 只能把不同 Layer 放到不同卡上, 如果单层模型本身加上前向传播中间激活值(Activations)超出了单张 GPU 的显存容量, PP 也无能为力.

* TP 能够将单层内巨大的权重和激活直接切碎分摊到多张卡上.

#### 2 超低延迟要求(Latency reduction for Inference)

* 在 LLM 推理(尤其生成阶段 Decode Phase, Batch Size 通常较小)中, 计算受限于显存带宽(Memory Bound).

* 数据并行(DP)无法降低单个请求的推理延迟.

* TP 将单个 Token 的计算算力分散到 N 张 GPU 上并行处理, 极大缩短了每个 Token 的生成时间, 是实现实时交互(Low-latency Streaming)的核心技术.

#### 3 消除流水线并行 (PP) 的气泡(Pipeline Bubbles)

* PP 在批处理时会产生待机等待(Bubble). TP 则是同步计算, 每个 Step 内部多卡并行, 不需要等待 Memory/Compute 槽位填充, 利用率更高.

#### 4 适合单机多卡的高带宽互联环境(NVLink)

* TP 在每一层都有频度极高的通信(如每层 2 次 All-Reduce). 这种通信频率在跨节点(以太网/InfiniBand)会极其缓慢.

* 但现代 AI 服务器单机内(如 8x H100/A100)拥有高达 900GB/s 的 NVLink, 极高的通信带宽使得 TP 在单机 8 卡范围内能够获得近乎线性的加速比. 因此 TP 通常作为 3D 并行(DP + PP + TP)中最内层(单机内)的并行策略.

### 3. 代码示例: 如何在 PyTorch 中使用 Tensor Parallel

PyTorch 从 2.0+ 开始推出了原生的 `torch.distributed.tensor.parallel`(基于 `DTensor` 构建), 使得使用 TP 变得非常优雅和模块化, 不再需要手动写繁琐的 `dist.all_reduce` 通信.

下面我展示两个维度的代码实现:

1. PyTorch 2.x 官方原生 API(推荐的高层使用方式)

2. 基于 PyTorch 自定义算子的底层原理示意(帮助深刻理解内部逻辑)

---

#### 示例 1: 使用 PyTorch 原生 `tensor.parallel` API (PyTorch 2.x+)

这是目前标准、简洁且生产可用的方式.

```python
# tp_example.py
# 运行方式: torchrun --nproc_per_node=2 tp_example.py

import os
import torch
import torch.nn as nn
import torch.distributed as dist

# 导入 PyTorch Distributed Tensor Parallel API
from torch.distributed.device_mesh import init_device_mesh
from torch.distributed.tensor.parallel import (
    parallelize_module,
    ColwiseParallel,
    RowwiseParallel,
    PairwiseParallel,
)


# 1. 定义一个标准的 Transformer MLP 模块
class ToyMLP(nn.Module):
    def __init__(self, hidden_dim: int):
        super().__init__()
        # 假设 hidden_dim -> 4 * hidden_dim -> hidden_dim
        self.in_proj = nn.Linear(hidden_dim, hidden_dim * 4, bias=False)
        self.act = nn.GELU()
        self.out_proj = nn.Linear(hidden_dim * 4, hidden_dim, bias=False)

    def forward(self, x):
        return self.out_proj(self.act(self.in_proj(x)))


def main():
    # 初始化分布式环境 (NCCL)
    dist.init_process_group("nccl")
    rank = dist.get_rank()
    world_size = dist.get_world_size()
    torch.cuda.set_device(rank)

    # 创建 DeviceMesh (设备网格), 这里定义 1D 的 TP 网格, 网格大小为 world_size
    device_mesh = init_device_mesh("cuda", mesh_shape=(world_size,))

    # 实例化普通模型
    hidden_dim = 1024
    model = ToyMLP(hidden_dim).to(f"cuda:{rank}")

    print(f"[Rank {rank}] 转换前 Linear1 权重形状: {model.in_proj.weight.shape}")

    # --- 核心: 应用 Tensor Parallelism ---
    # 方式 A: 使用预定义的 PairwiseParallel (专门优化 MLP 结构: 第一层列并行, 第二层行并行)
    tp_model = parallelize_module(
        module=model, device_mesh=device_mesh, parallelize_plan=PairwiseParallel()
    )

    # 方式 B: 也可以通过 Dict 精细化指定层:
    # tp_plan = {
    #     "in_proj": ColwiseParallel(),
    #     "out_proj": RowwiseParallel(),
    # }
    # tp_model = parallelize_module(model, device_mesh, tp_plan)

    # 查看切分后的权重形状
    # 原本 4096 x 1024 的 in_proj, 在 2 卡上切分后, 每张卡只保存 2048 x 1024
    print(
        f"[Rank {rank}] 转换后(TP) in_proj 局部权重形状: {tp_model.in_proj.weight.to_local().shape}"
    )
    print(
        f"[Rank {rank}] 转换后(TP) out_proj 局部权重形状: {tp_model.out_proj.weight.to_local().shape}"
    )

    # 前向传播测试
    input_data = torch.randn(8, 128, hidden_dim, device=f"cuda:{rank}")
    output = tp_model(input_data)

    print(f"[Rank {rank}] 输出 Shape: {output.shape}")

    dist.destroy_process_group()


if __name__ == "__main__":
    main()

```

#### 示例 2: 手动实现 Column/Row Parallel(揭秘底层通信)

如果你想了解底层是如何通过 `torch.distributed` 手动拼接张量和管理反向传播梯度的, 可以看下面这个 Megatron-style 的纯逻辑实现:

```python
import torch
import torch.nn as nn
import torch.distributed as dist


# 1. 自定义支持全收集 (All-Gather) 的 Autograd Function
class _CopyToModelParallelRegion(torch.autograd.Function):
    """前向传播不做任何事(直接 Pass), 反向传播执行 All-Reduce"""

    @staticmethod
    def forward(ctx, input_):
        return input_

    @staticmethod
    def backward(ctx, grad_output):
        # 梯度自动累加
        dist.all_reduce(grad_output, op=dist.ReduceOp.SUM)
        return grad_output


class _ReduceFromModelParallelRegion(torch.autograd.Function):
    """前向传播执行 All-Reduce, 反向传播不做任何事"""

    @staticmethod
    def forward(ctx, input_):
        dist.all_reduce(input_, op=dist.ReduceOp.SUM)
        return input_

    @staticmethod
    def backward(ctx, grad_output):
        return grad_output


# 2. 手动实现列并行 Linear (Column Parallel)
class ManualColumnParallelLinear(nn.Module):
    def __init__(self, in_features, out_features, world_size, rank):
        super().__init__()
        # 在列维度拆分 out_features
        self.out_features_per_partition = out_features // world_size
        self.weight = nn.Parameter(
            torch.empty(self.out_features_per_partition, in_features)
        )
        nn.init.kaiming_uniform_(self.weight)

    def forward(self, x):
        # 前向: X 不变, 直接与局部 Weight 做矩阵乘法
        # x: [batch, in_features]
        # weight: [out_features / k, in_features]
        # output: [batch, out_features / k]
        input_parallel = _CopyToModelParallelRegion.apply(x)
        return nn.functional.linear(input_parallel, self.weight)


# 3. 手动实现行并行 Linear (Row Parallel)
class ManualRowParallelLinear(nn.Module):
    def __init__(self, in_features, out_features, world_size, rank):
        super().__init__()
        # 在行维度拆分 in_features
        self.in_features_per_partition = in_features // world_size
        self.weight = nn.Parameter(
            torch.empty(out_features, self.in_features_per_partition)
        )
        nn.init.kaiming_uniform_(self.weight)

    def forward(self, x):
        # x 输入本身已经是被切分好的 [batch, in_features / k]
        # 局部计算 [batch, out_features]
        output_parallel = nn.functional.linear(x, self.weight)
        # 前向结束前做一次 All-Reduce, 聚合所有 GPU 的局部和
        output = _ReduceFromModelParallelRegion.apply(output_parallel)
        return output

```

### 总结比较

| 特性 / 维度 | Data Parallelism (DP)    | Pipeline Parallelism (PP)   | Tensor Parallelism (TP)                  |
| :---------- | :----------------------- | :-------------------------- | :--------------------------------------- |
| 切分维度    | Batch 维度               | 模型 Layer 层数维度         | 单层内的 Weight/Tensor 维度              |
| 通信频率    | 较低(每个 Step 结束一次) | 中等(P2P 传递 Layer 激活值) | 极高(每一层 1-2 次 All-Reduce)           |
| 硬件要求    | 普通网络/跨节点均可      | 高带宽/跨节点               | 强烈依赖 NVLink / 高带宽 intra-node 网络 |
| 适用场景    | 扩充训练 Batch Size      | 模型层数极多, 单卡装不下    | 超大单层参数、极低推理延迟要求           |

在现代大模型工程(如 DeepSpeed, Megatron-LM, vLLM, PyTorch Distributed)实践中, 我们通常将 TP 放在节点内(如 8 卡 NVLink), 将 PP / DP / ZeRO 放在节点间, 形成高效的 3D 并行混合架构.

该脚本基于 PyTorch 原生的 `torch.distributed.device_mesh` 和 `torch.distributed.tensor.parallel` API, 包含了: TP 并行化映射、同步随机数据生成、完整前反向传播训练、分布式 Checkpoint 导出与保存, 以及资源回收.

### 1. 完整 PyTorch TP 训练脚本 (`train_tp.py`)

将以下代码保存为文件 `train_tp.py`:

```python
import os
import torch
import torch.nn as nn
import torch.distributed as dist
from torch.distributed.device_mesh import init_device_mesh
from torch.distributed.tensor.parallel import (
    parallelize_module,
    ColwiseParallel,
    RowwiseParallel,
)
from torch.distributed.checkpoint.state_dict import get_model_state_dict


# -----------------------------------------------------------------------------
# 1. 原始模型定义 (保持你的模型结构不变)
# -----------------------------------------------------------------------------
class TransformerBlock(nn.Module):
    def __init__(self, dim: int):
        super().__init__()
        self.linear1 = nn.Linear(dim, dim * 4)
        self.act = nn.GELU()
        self.linear2 = nn.Linear(dim * 4, dim)

    def forward(self, x):
        return x + self.linear2(self.act(self.linear1(x)))


class SimpleLLM(nn.Module):
    def __init__(self, vocab_size=10000, dim=2048, num_layers=4):
        super().__init__()
        self.embed = nn.Embedding(vocab_size, dim)
        self.layers = nn.ModuleList([TransformerBlock(dim) for _ in range(num_layers)])
        self.head = nn.Linear(dim, vocab_size)

    def forward(self, x):
        x = self.embed(x)
        for layer in self.layers:
            x = layer(x)
        return self.head(x)


# -----------------------------------------------------------------------------
# 2. 分布式环境初始化与清理
# -----------------------------------------------------------------------------
def setup_distributed():
    """初始化分布式进程组 (NCCL)"""
    dist.init_process_group("nccl")
    local_rank = int(os.environ["LOCAL_RANK"])
    rank = int(os.environ["RANK"])
    world_size = int(os.environ["WORLD_SIZE"])
    torch.cuda.set_device(local_rank)
    return rank, local_rank, world_size


def cleanup():
    """销毁进程组, 回收 GPU 资源"""
    dist.destroy_process_group()


# -----------------------------------------------------------------------------
# 3. 主训练流程
# -----------------------------------------------------------------------------
def train():
    rank, local_rank, world_size = setup_distributed()
    device = torch.device(f"cuda:{local_rank}")

    if rank == 0:
        print(f"[Init] 开始初始化单机 {world_size} 卡 TP 训练环境...")

    # 超参数配置
    vocab_size = 10000
    dim = 2048
    num_layers = 4
    batch_size = 4
    seq_len = 128
    num_steps = 10

    # A. 创建 DeviceMesh (设备网格)
    # 对于纯 1D TP, 创建维度为 (world_size,) 的 1D Mesh
    tp_mesh = init_device_mesh("cuda", (world_size,))

    # B. 实例化原始模型并移动到当前 GPU
    model = SimpleLLM(vocab_size=vocab_size, dim=dim, num_layers=num_layers).to(device)

    # C. 应用 Tensor Parallelism (TP)
    # Megatron 风格经典方案:
    # TransformerBlock 中的 MLP: linear1 做列并行 (Colwise), linear2 做行并行 (Rowwise)
    for layer in model.layers:
        parallelize_module(
            module=layer,
            device_mesh=tp_mesh,
            parallelize_plan={
                "linear1": ColwiseParallel(),
                "linear2": RowwiseParallel(),
            },
        )

    if rank == 0:
        print("[TP Setup] 已成功为所有 TransformerBlock 应用列并行与行并行切分!")

    # D. 优化器与损失函数
    optimizer = torch.optim.AdamW(model.parameters(), lr=1e-4)
    criterion = nn.CrossEntropyLoss()

    # E. 训练循环
    model.train()
    for step in range(1, num_steps + 1):
        optimizer.zero_grad()

        # [重点]TP 模式下, 所有卡需要接收相同的 Input Batch (Data Replicated)
        # 通过固定相同的 random seed 来保证 8 张卡生成的 Dummy 数据完全一致
        torch.manual_seed(42 + step)
        input_ids = torch.randint(0, vocab_size, (batch_size, seq_len), device=device)
        targets = torch.randint(0, vocab_size, (batch_size, seq_len), device=device)

        # 前向传播
        outputs = model(input_ids)  # Shape: [batch_size, seq_len, vocab_size]

        # 计算 Loss
        loss = criterion(outputs.view(-1, vocab_size), targets.view(-1))

        # 反向传播与优化
        loss.backward()
        optimizer.step()

        if rank == 0:
            print(f"Step [{step}/{num_steps}] - Loss: {loss.item():.4f}")

    # -------------------------------------------------------------------------
    # 4. 模型保存 (Save Model State Dict)
    # -------------------------------------------------------------------------
    if rank == 0:
        print("\n[Save] 开始聚合全量模型权重并保存...")

    # PyTorch 提供 get_model_state_dict 自动将各个 GPU 上的分布式张量 (DTensor)
    # 聚合并还原为单卡/CPU 上的完整 state_dict, 屏蔽了底层切分细节
    full_state_dict = get_model_state_dict(model)

    if rank == 0:
        os.makedirs("checkpoints", exist_ok=True)
        save_path = "checkpoints/simple_llm_tp.pt"
        torch.save(full_state_dict, save_path)
        print(f"[Save] 完整模型权重已成功保存至: {save_path}")

    # 同步等待 Rank 0 完成保存操作
    dist.barrier()


# -----------------------------------------------------------------------------
# 5. 脚本入口与异常防护 (资源回收)
# -----------------------------------------------------------------------------
if __name__ == "__main__":
    try:
        train()
    finally:
        # 确保无论发生什么异常, 最终都能正确释放 PyTorch NCCL 资源
        cleanup()

```

---

### 2. 核心技术细节说明

1. 并行计划定义 (`parallelize_module`):

   * 我们遍历了 `model.layers` 中的每一个 `TransformerBlock`.

   * 对 `linear1` 使用 `ColwiseParallel()`(列并行): 权重在 $Dim \to 4 \times Dim$ 扩展维度切分为 8 份, 每卡只算 $\frac{1}{8}$.

   * 对 `linear2` 使用 `RowwiseParallel()`(行并行): 权重在 $4 \times Dim \to Dim$ 缩减维度切分为 8 份, 并在结尾自动触发 All-Reduce 通信将各卡结果求和.

2. 数据的同步处理 (Input Replication):

   * 在纯 Tensor Parallel 下, 所有 GPU 处理的 Batch 必须是一模一样的.

   * 代码中通过在每个 step 设置相同的全局 seed (`torch.manual_seed(42 + step)`), 保证 8 个进程生成的 `input_ids` 完全相同.

3. 分布式 Checkpoint 保存 (`get_model_state_dict`):

   * 由于模型参数已被转为分布式的 `DTensor`, 直接使用 `model.state_dict()` 得到的是被切碎的 Tensor.

   * 采用 PyTorch 官方的 `get_model_state_dict(model)` API, 它能在后台自动将切分的张量通过通信 Gather 回 Rank 0, 直接保存为一个无需依赖 TP 即可在单卡重新加载的标准 `.pt` 文件.

4. 资源清理与回收 (`cleanup`):

   * 使用 `try...finally` 结构包裹 `train()` 逻辑. 无论因报错中断还是正常结束, 都会确保执行 `dist.destroy_process_group()`, 释放 GPU 显存和 NCCL 套接字通信句柄.

### 1. 完整多机多卡 TP 训练脚本 (`train_multi_node_tp.py`)

将以下脚本保存为 `train_multi_node_tp.py`(两台机器上都需要放置这份完全相同的代码):

```python
import os
import torch
import torch.nn as nn
import torch.distributed as dist
from torch.distributed.device_mesh import init_device_mesh
from torch.distributed.tensor.parallel import (
    parallelize_module,
    ColwiseParallel,
    RowwiseParallel,
)
from torch.distributed.checkpoint.state_dict import get_model_state_dict


# -----------------------------------------------------------------------------
# 1. 原始模型定义 (保持结构不变)
# -----------------------------------------------------------------------------
class TransformerBlock(nn.Module):
    def __init__(self, dim: int):
        super().__init__()
        self.linear1 = nn.Linear(dim, dim * 4)
        self.act = nn.GELU()
        self.linear2 = nn.Linear(dim * 4, dim)

    def forward(self, x):
        return x + self.linear2(self.act(self.linear1(x)))


class SimpleLLM(nn.Module):
    def __init__(self, vocab_size=10000, dim=2048, num_layers=4):
        super().__init__()
        self.embed = nn.Embedding(vocab_size, dim)
        self.layers = nn.ModuleList([TransformerBlock(dim) for _ in range(num_layers)])
        self.head = nn.Linear(dim, vocab_size)

    def forward(self, x):
        x = self.embed(x)
        for layer in self.layers:
            x = layer(x)
        return self.head(x)


# -----------------------------------------------------------------------------
# 2. 跨节点分布式环境初始化与清理
# -----------------------------------------------------------------------------
def setup_distributed():
    """初始化跨节点 NCCL 进程组"""
    dist.init_process_group("nccl")

    # 环境变量由 torchrun 自动注入
    global_rank = int(os.environ["RANK"])  # 0 ~ 15
    local_rank = int(os.environ["LOCAL_RANK"])  # 0 ~ 7 (单机内的 GPU 编号)
    world_size = int(os.environ["WORLD_SIZE"])  # 16

    # 将当前进程绑定到本机的对应 GPU 上
    torch.cuda.set_device(local_rank)
    return global_rank, local_rank, world_size


def cleanup():
    """清理进程组, 释放跨节点 NCCL 连接与 GPU 资源"""
    if dist.is_initialized():
        dist.destroy_process_group()


# -----------------------------------------------------------------------------
# 3. 主训练流程
# -----------------------------------------------------------------------------
def train():
    global_rank, local_rank, world_size = setup_distributed()
    device = torch.device(f"cuda:{local_rank}")

    if global_rank == 0:
        print(f"[Init] 成功建立跨节点集群! 总卡数 (WORLD_SIZE): {world_size}")

    # 超参数配置
    vocab_size = 10000
    dim = 2048
    num_layers = 4
    batch_size = 4
    seq_len = 128
    num_steps = 10

    # A. 初始化 1D DeviceMesh, 将 16 张 GPU 编排在同一个 TP 网格中
    tp_mesh = init_device_mesh("cuda", (world_size,))

    # B. 实例化模型并移动到本地 GPU
    model = SimpleLLM(vocab_size=vocab_size, dim=dim, num_layers=num_layers).to(device)

    # C. 应用跨 16 卡的 Tensor Parallelism
    # 将矩阵切分为 16 份 (Colwise) 和 16 份 (Rowwise)
    for layer in model.layers:
        parallelize_module(
            module=layer,
            device_mesh=tp_mesh,
            parallelize_plan={
                "linear1": ColwiseParallel(),
                "linear2": RowwiseParallel(),
            },
        )

    if global_rank == 0:
        print(
            f"[TP Setup] 已在全部 {world_size} 张 GPU 上完成层内张量切分 (16-way TP)!"
        )

    # D. 优化器与损失函数
    optimizer = torch.optim.AdamW(model.parameters(), lr=1e-4)
    criterion = nn.CrossEntropyLoss()

    # E. 训练循环
    model.train()
    for step in range(1, num_steps + 1):
        optimizer.zero_grad()

        # [重点]TP 模式要求全网 16 张 GPU 必须接收完全相同的输入 Batch
        # 跨节点保证随机种子一致:
        torch.manual_seed(42 + step)
        input_ids = torch.randint(0, vocab_size, (batch_size, seq_len), device=device)
        targets = torch.randint(0, vocab_size, (batch_size, seq_len), device=device)

        # 前向传播 (跨节点 16 卡同步计算与 All-Reduce 通信)
        outputs = model(input_ids)

        # 计算 Loss
        loss = criterion(outputs.view(-1, vocab_size), targets.view(-1))

        # 反向传播与优化
        loss.backward()
        optimizer.step()

        if global_rank == 0:
            print(f"Step [{step}/{num_steps}] - Loss: {loss.item():.4f}")

    # -------------------------------------------------------------------------
    # 4. 跨节点权重聚合与模型保存
    # -------------------------------------------------------------------------
    if global_rank == 0:
        print("\n[Save] 开始跨节点收集 16 卡权重并还原为完整模型...")

    # get_model_state_dict 会在后台将分散在 2 台机器 16 张 GPU 上的 DTensor 汇总到 Global Rank 0
    full_state_dict = get_model_state_dict(model)

    # 仅由 Node 0 的 Rank 0 写入磁盘, 避免多节点文件写入冲突
    if global_rank == 0:
        os.makedirs("checkpoints", exist_ok=True)
        save_path = "checkpoints/simple_llm_multi_tp.pt"
        torch.save(full_state_dict, save_path)
        print(f"[Save] 跨节点聚合后的完整权重已成功保存至: {save_path}")

    # 全局同步, 防止主节点保存完后子节点提前退出导致通信中断
    dist.barrier()


# -----------------------------------------------------------------------------
# 5. 入口与资源回收
# -----------------------------------------------------------------------------
if __name__ == "__main__":
    try:
        train()
    finally:
        cleanup()

```

### 2. 核心逻辑解析

1. 并行配置 (`parallelize_module`):

   * 原始 `linear1` 的权重尺寸为 `[8192, 2048]`, 在 8 卡列并行后, 每张卡实际保存的局部权重尺寸仅为 `[1024, 2048]`(显存仅占原来的 1/8).

   * 原始 `linear2` 的权重尺寸为 `[2048, 8192]`, 在 8 卡行并行后, 每张卡实际保存的局部权重尺寸为 `[2048, 1024]`.

2. 输入同步 (Data Replication):

   * TP 的本质是"单数据、多算子并行". 因此在每个 step 训练时, 通过 `torch.manual_seed(42 + step)` 确保 8 张卡上生成的 `input_ids` 和 `targets` 保持完全相同.

3. 模型保存 (`get_model_state_dict`):

   * 直接对带有 TP 的模型使用 `torch.save(model.state_dict())` 保存的是切碎的张量片段.

   * 使用官方的 `get_model_state_dict(model)` API 能够自动将 8 张卡上的 `DTensor` 全局收集并恢复为普通的 `torch.Tensor`, 保存出的 `.pt` 权重文件后续可以直接在任意单卡上恢复使用.

### 1. 完整跨节点训练脚本 (`train_tp_multi_node.py`)

请将以下代码保存为 `train_tp_multi_node.py`, 并确保两台机器上都放置了这份完全相同的代码:

```python
import os
import torch
import torch.nn as nn
import torch.distributed as dist
from torch.distributed.device_mesh import init_device_mesh
from torch.distributed.tensor.parallel import (
    parallelize_module,
    ColwiseParallel,
    RowwiseParallel,
)
from torch.distributed.checkpoint.state_dict import get_model_state_dict


# -----------------------------------------------------------------------------
# 1. 原始模型定义 (结构保持不变)
# -----------------------------------------------------------------------------
class TransformerBlock(nn.Module):
    def __init__(self, dim: int):
        super().__init__()
        self.linear1 = nn.Linear(dim, dim * 4)
        self.act = nn.GELU()
        self.linear2 = nn.Linear(dim * 4, dim)

    def forward(self, x):
        return x + self.linear2(self.act(self.linear1(x)))


class SimpleLLM(nn.Module):
    def __init__(self, vocab_size=10000, dim=2048, num_layers=4):
        super().__init__()
        self.embed = nn.Embedding(vocab_size, dim)
        self.layers = nn.ModuleList([TransformerBlock(dim) for _ in range(num_layers)])
        self.head = nn.Linear(dim, vocab_size)

    def forward(self, x):
        x = self.embed(x)
        for layer in self.layers:
            x = layer(x)
        return self.head(x)


# -----------------------------------------------------------------------------
# 2. 跨节点分布式环境初始化与清理
# -----------------------------------------------------------------------------
def setup_distributed():
    """初始化跨节点 NCCL 进程组"""
    dist.init_process_group("nccl")

    # 环境变量由各节点上的 torchrun 自动传入
    global_rank = int(os.environ["RANK"])  # 全局卡号: 0 ~ 15
    local_rank = int(os.environ["LOCAL_RANK"])  # 本机卡号: 0 ~ 7
    world_size = int(os.environ["WORLD_SIZE"])  # 全局总卡数: 16

    # 锁定当前进程使用的本机 GPU 编号
    torch.cuda.set_device(local_rank)
    return global_rank, local_rank, world_size


def cleanup():
    """销毁进程组, 释放跨节点通信套接字与 GPU 显存"""
    if dist.is_initialized():
        dist.destroy_process_group()


# -----------------------------------------------------------------------------
# 3. 主训练流程
# -----------------------------------------------------------------------------
def train():
    global_rank, local_rank, world_size = setup_distributed()
    device = torch.device(f"cuda:{local_rank}")

    # 仅由全局主节点 (Global Rank 0) 打印日志
    if global_rank == 0:
        print(f"[Init] 成功建立跨节点集群! 全局总卡数 (WORLD_SIZE): {world_size}")

    # 超参数定义
    vocab_size = 10000
    dim = 2048
    num_layers = 4
    batch_size = 4
    seq_len = 128
    num_steps = 10

    # A. 构建跨 16 卡的 1D 设备网格 (DeviceMesh)
    # PyTorch 会自动根据通信链路将 2 台机器的 16 张 GPU 映射为一维网格
    tp_mesh = init_device_mesh("cuda", (world_size,))

    # B. 实例化模型并移动到对应的本地 GPU 设备
    model = SimpleLLM(vocab_size=vocab_size, dim=dim, num_layers=num_layers).to(device)

    # C. 为模型应用 16-way Tensor Parallelism
    # 将线性层权重切分为 16 份 (列并行/行并行)
    for layer in model.layers:
        parallelize_module(
            module=layer,
            device_mesh=tp_mesh,
            parallelize_plan={
                "linear1": ColwiseParallel(),
                "linear2": RowwiseParallel(),
            },
        )

    if global_rank == 0:
        print(f"[TP Setup] 已在全网 {world_size} 张 GPU 上完成张量并行切分!")

    # D. 定义优化器与损失函数
    optimizer = torch.optim.AdamW(model.parameters(), lr=1e-4)
    criterion = nn.CrossEntropyLoss()

    # E. 训练循环
    model.train()
    for step in range(1, num_steps + 1):
        optimizer.zero_grad()

        # [重点]TP 属于张量并行, 要求全网 16 张 GPU 处理完全相同的输入 Batch
        # 通过统一的随机种子保证 16 张卡上的输入 Tensor 完全一致:
        torch.manual_seed(42 + step)
        input_ids = torch.randint(0, vocab_size, (batch_size, seq_len), device=device)
        targets = torch.randint(0, vocab_size, (batch_size, seq_len), device=device)

        # 前向传播 (触发跨节点的列并行矩阵乘法与行并行 All-Reduce 通信)
        outputs = model(input_ids)

        # 计算 Loss
        loss = criterion(outputs.view(-1, vocab_size), targets.view(-1))

        # 反向传播与梯度更新
        loss.backward()
        optimizer.step()

        if global_rank == 0:
            print(f"Step [{step:02d}/{num_steps:02d}] - Loss: {loss.item():.4f}")

    # -------------------------------------------------------------------------
    # 4. 跨节点权重聚合与模型保存
    # -------------------------------------------------------------------------
    if global_rank == 0:
        print("\n[Save] 开始跨节点收集 16 张卡上的切分权重并还原...")

    # get_model_state_dict 在后台通过通信将分布在 2 台机器上的 16 份 DTensor
    # 全局收集并拼回为单卡/CPU 格式的完整权重字典
    full_state_dict = get_model_state_dict(model)

    # 仅由 Node 0 的 Global Rank 0 负责落盘, 避免多机器竞争写文件
    if global_rank == 0:
        os.makedirs("checkpoints", exist_ok=True)
        save_path = "checkpoints/simple_llm_multi_node_tp.pt"
        torch.save(full_state_dict, save_path)
        print(f"[Save] 完整模型已成功保存至: {save_path}")

    # 全局同步屏障, 确保所有节点都等待主节点保存完毕
    dist.barrier()


# -----------------------------------------------------------------------------
# 5. 主程序入口与异常资源回收
# -----------------------------------------------------------------------------
if __name__ == "__main__":
    try:
        train()
    finally:
        # 使用 try...finally 防护, 确保脚本无论正常结束还是中断, 都能销毁 NCCL 进程组
        cleanup()

```

### 3. 多机训练的关键参数与排坑指南

1. `torchrun` 跨节点参数详解:

2. 跨节点网络接口设置 (`NCCL_SOCKET_IFNAME`):

   ```bash
   # 如果有 IB 物理网卡, 开启 RDMA 高速通信:
   export NCCL_IB_DISABLE=0
   ```

3. 数据一致性 (Input Replication):

   TP 模式下, 全网所有的 GPU 算子属于同一次前向计算图的分块. 因此代码中通过 `torch.manual_seed(42 + step)` 保证了 2 台机器共 16 张 GPU 在每一个 step 生成的 `input_ids` 绝无差异.

### 一、从纯文本到矩阵: 分词与张量化

计算机无法直接处理自然语言文本, 在进入模型前必须经过三个阶段:

```
[原始文本]
   │  分词 (Tokenization)
   ▼
[Token 序列 (字符串)]
   │  词表映射 (Vocab Lookup)
   ▼
[Token ID 序列 (1D 整数列表)]
   │  批处理对齐 (Batching & Padding)
   ▼
[输入张量矩阵 (2D 整数 Tensor: shape=[B, S])]
   │  词嵌入查找 (Embedding Lookup)
   ▼
[隐藏层激活矩阵 (3D 浮点 Tensor: shape=[B, S, Dim])]
```

1. 分词(Tokenization)与 ID 映射:
   - 原始文本如 `"Hello TP"` 会被切分成若干 token, 如 `["Hello", " ", "TP"]`.
   - 每个 token 在词表(Vocabulary, 大小为 `vocab_size`)中拥有唯一的整数索引(ID), 如 `[105, 32, 894]`.
2. 批处理与形状(Batching & Padding):
   - 将多个样本组织为一个 Batch, 并补齐到统一长度 $S$(`seq_len`).
   - 得到输入张量 $X_{\text{input}} \in \mathbb{Z}^{B \times S}$(形状为 `[Batch_Size, Seq_Len]`, 类型为 `torch.long`).
3. Embedding 变换:
   - 输入矩阵的每个整数 ID 作为行索引, 从大小为 `[vocab_size, dim]` 的权重矩阵中查找对应行, 输出形状为 `[B, S, dim]` 的三维浮点张量.

---

### 二、8 卡通信组(Process Group)的形成原理

在 PyTorch 分布式框架中, 多卡并行基于 多进程模型(Multi-Process):
1. 环境变量: `torchrun` 在启动 8 个进程时会自动注入环境变量:
   - `RANK`: 当前进程的全局唯一编号(`0` ~ `7`).
   - `WORLD_SIZE`: 总进程数(`8`).
   - `LOCAL_RANK`: 当前进程在当前单机上的物理 GPU 编号(`0` ~ `7`).
   - `MASTER_ADDR` 与 `MASTER_PORT`: 进程间建立 TCP 同步连接的 IP 与端口.
2. 设备绑定: 每个进程通过 `torch.cuda.set_device(local_rank)` 绑定对应的一张独立物理显卡.
3. 通信组初始化:
   - 调用 `dist.init_process_group(backend="nccl")` 后, 各个独立进程通过 TCP 握手, 初始化 NVIDIA NCCL 底层库.
   - NCCL 会自动探测硬件拓扑(如 NVLink / NVSwitch / PCIe), 构建环形(Ring)或树状(Tree)的高速硬件传输拓扑.
   - 此时默认的全局通信组(World Group)建立完成, 8 张卡拥有了互相发送、聚合(Reduce)、收集(Gather)张量的能力.

### 三、模型算子的 TP 切分与通信数学原理

对于本例中的模型, 各层切分策略如下:

```
                    ┌─────────────────────────┐
                    │  Input: [B, S] (Token)  │
                    └────────────┬────────────┘
                                 │
           ┌─────────────────────▼─────────────────────┐
           │ VocabParallelEmbedding: [V/8, Dim]        │
           │ Local Lookup -> [B, S, Dim]               │
           │ dist.all_reduce (SUM)                     │
           └─────────────────────┬─────────────────────┘
                                 │ [B, S, Dim] (Full)
           ┌─────────────────────▼─────────────────────┐
 ┌─────────┤            TransformerBlock               ├─────────┐
 │         └─────────────────────┬─────────────────────┘         │
 │ (Residual)                    │                               │
 │         ┌─────────────────────▼─────────────────────┐         │
 │         │ ColumnParallelLinear: [Dim, 4*Dim/8]      │         │
 │         │ Local Matmul -> GELU -> [B, S, 4*Dim/8]   │         │
 │         └─────────────────────┬─────────────────────┘         │
 │                               │ [B, S, 4*Dim/8] (No Comm)     │
 │         ┌─────────────────────▼─────────────────────┐         │
 │         │ RowParallelLinear: [4*Dim/8, Dim]         │         │
 │         │ Local Matmul -> [B, S, Dim]               │         │
 │         │ dist.all_reduce (SUM) -> [B, S, Dim]      │         │
 │         └─────────────────────┬─────────────────────┘         │
 │                               │                               │
 └──────────────────────────────>⊕ (x + MLP(x))                 │
                                 │                               │
           ┌─────────────────────▼─────────────────────┐         │
           │               Next Layers ...             │◄────────┘
           └─────────────────────┬─────────────────────┘
                                 │ [B, S, Dim]
           ┌─────────────────────▼─────────────────────┐
           │ ColumnParallelHead: [Dim, V/8]            │
           │ Local Matmul -> [B, S, V/8]               │
           │ dist.all_gather_into_tensor               │
           │ Reshape -> [B, S, V]                      │
           └─────────────────────┬─────────────────────┘
                                 │
                    ┌────────────▼────────────┐
                    │  Output: [B, S, Vocab]  │
                    └─────────────────────────┘
```

1. Embedding 层(按词表切分, Vocab-Parallel):
   - 权重按词表维度切分: 每张卡仅保存 `[vocab_size / 8, dim]` 大小的词表切片.
   - 前向计算: 如果 Token 不在本卡负责的 ID 区间内, 输出置 0; 如果在区间内则执行局部查表. 最后执行 `dist.all_reduce(SUM)`, 将 8 张卡的局部查表结果相加, 得到完整的 `[B, S, dim]`.
2. Linear1(Column Parallel, 列并行):
   - 权重按输出维度列切分: $W_1 = [W_{1,0}, W_{1,1}, \dots, W_{1,7}]$, 每张卡权重为 `[dim, 4*dim / 8]`.
   - 输入为完整的 $[B, S, \text{dim}]$, 本地矩阵乘法得到局部输出 $[B, S, 4*\text{dim} / 8]$.
   - 此时不需要任何通信, 各卡独立将局部特征送入 GELU 激活函数.
3. Linear2(Row Parallel, 行并行):
   - 权重按输入维度行切分: $W_2 = [W_{2,0}^T, W_{2,1}^T, \dots, W_{2,7}^T]^T$, 每张卡权重为 `[4*dim / 8, dim]`.
   - 本地矩阵乘法: $[B, S, 4*\text{dim} / 8] \times [4*\text{dim} / 8, \text{dim}] \to [B, S, \text{dim}]$.
   - 通信: 通过 `dist.all_reduce(SUM)` 将 8 张卡的局部内积求和, 还原出数学上等价的完整输出 $[B, S, \text{dim}]$.
   - 残差相加(Residual Add): 各卡本地独立执行 $X + Y$.
4. Head 层(Column Parallel + All-Gather):
   - 权重切分为 `[dim, vocab_size / 8]`, 计算局部 Logits $[B, S, \text{vocab\_size} / 8]$.
   - 使用 `dist.all_gather_into_tensor` 收集 8 张卡上的分片, 重组得到完整的 $[B, S, \text{vocab\_size}]$.

### 二、2 台机器(16 卡)如何形成通信组

### 二、FSDP2 反向传播时如何更新梯度? 和 DDP 一样吗?

结论: FSDP2 与 DDP 在反向传播和更新机制上有本质不同.

在 DDP 中, 各卡独立反向求出当前卡全量参数的梯度, 然后调用 `dist.all_reduce` 让所有卡都得到一份全量平均梯度, 最后每张卡上的优化器更新全量参数.

而在 FSDP2 中, 为了实现参数、梯度、优化器状态的"三重全分片(Zero-3)", 反向传播与更新经历以下 5 个关键步骤:

```
[FSDP2 反向传播生命周期(以单层为例)]
1. 再次触发 All-Gather  ---> 收集该层完整权重 W_full(因为前向算完已释放)
2. 本地计算全量梯度      ---> 计算出 ∇W_full = X^T · dL/dY(临时占用显存)
3. 立即释放 W_full      ---> 显存优化
4. 触发 Reduce-Scatter  ---> 将 8 卡的 ∇W_full 累加求和, 但直接切片分发给对应 Rank
5. 优化器本地更新        ---> 本卡只更新属于自己的 1/8 权重切片 (W_shard -= lr * ∇W_shard)
```

#### 核心差异对比:

| 特性           | DDP                                           | FSDP2                                                   |
| :------------- | :-------------------------------------------- | :------------------------------------------------------ |
| 反向传播通信 1 | 无通信(直接反向)                              | `All-Gather` 重新收集完整权重                           |
| 梯度同步通信 2 | `All-Reduce`(每张卡都持有全量梯度)            | `Reduce-Scatter`(求和并切分梯度)                        |
| 优化器状态占用 | 每张卡存 $100\%$ 的 Adam 状态 ($16 \times P$) | 每张卡仅存 $1/N$ 的 Adam 状态 ($\frac{16 \times P}{N}$) |
| 优化器更新行为 | 每张卡更新全部参数                            | 每张卡只更新属于自己的那 $1/N$ 分片参数                 |

> 关键机制: FSDP2 的优化器 `step()` 是完全本地、无卡间通信的, 因为每张卡在 `Reduce-Scatter` 后就已经拿到了自己负责的那部分平均梯度.

### 三、对于 TP, 反向传播时如何更新梯度?

在张量并行(Megatron-LM 风格)中, 前向传播和反向传播在通信原语上存在精妙的"数学对偶性(Conjugate Duality)".

`TP 不需要任何通信来同步参数梯度, 因为每张卡本来就只负责计算它拥有的那一小块子矩阵的梯度!`

以经典的 Transformer MLP(ColumnParallel -> RowParallel)为例:

```
        前向 (Forward)                           反向 (Backward)
--------------------------------------------------------------------------------------
输入 X                                   <--- 对 X 的梯度 ∇X  (触发 All-Reduce!)
  │                                             │
Linear1 (ColumnParallel: W_col)          <--- ∇W_col = X^T · ∇Y_local (本地纯计算, 无通信)
  │ (各卡算出局部分片 Y_local)                   │
GELU Act                                 <--- ∇Act (本地纯计算, 无通信)
  │ (局部分片 Z_local)                          │
Linear2 (RowParallel: W_row)             <--- ∇W_row = (Z_local)^T · ∇Out (本地纯计算, 无通信)
  │                                             │
All-Reduce (求和得到完整 Out)             <--- 上游梯度 ∇Out (各卡天然持有全量副本, 无通信)
```

#### TP 反向传播的计算与更新全流程:

1. RowParallel 的反向计算:
   * 上游反向传回来的梯度 $\nabla \text{Out}$ 在各卡已经是完整且相同的.
   * 本卡直接通过局部的激活值 $Z_{local}$ 计算本地权重梯度: $\nabla W_{row\_local} = Z_{local}^T \cdot \nabla \text{Out}$(无需通信!).
   * 传递给激活函数的梯度为 $\nabla Z_{local} = \nabla \text{Out} \cdot W_{row\_local}^T$(本地矩阵乘, 无需通信!).
2. ColumnParallel 的反向计算:
   * 通过 GELU 反向传播得到 $\nabla Y_{local}$.
   * 本卡直接计算列并行的本地权重梯度: $\nabla W_{col\_local} = X^T \cdot \nabla Y_{local}$(无需通信!).
   * 关键通信点: 计算输入 $X$ 的梯度时, 由于 $X$ 参与了各卡独立的列矩阵乘, 数学上 $\nabla X = \sum_{i=1}^{tp\_size} (\nabla Y_{local\_i} \cdot W_{col\_local\_i}^T)$. 因此, 在 ColumnParallel 的输入端必须触发一次 `dist.all_reduce` 来聚合 $\nabla X$!
3. 参数更新(Optimizer Step):
   * 每一张卡上求得的 $\nabla W_{col\_local}$ 和 $\nabla W_{row\_local}$ 天生就是当前卡分片权重的最终精确梯度.
   * 各卡的优化器直接对本地持有的子矩阵进行 `optimizer.step()`, 完全不需要跨卡通信.

### 四、FSDP2 和 TP 最根本的区别, 只是模型权重切分策略的不同吗?

不仅仅是权重切分维度的差异, 它们在并行范式、通信内容、硬件与网络依赖度上有着本质的鸿沟.

#### 1. 核心维度的本质区别矩阵

| 维度             | FSDP2 (Fully Sharded DP)                                 | TP (Tensor Parallelism)                                         |
| :--------------- | :------------------------------------------------------- | :-------------------------------------------------------------- |
| 所属并行流派     | 数据并行 (Data Parallelism)                              | 模型张量并行 (Model Parallelism)                                |
| 切分的对象       | 切分 Batch 维度(数据切片)+ 权重在存储时展平切片          | 切分 Hidden/Vocab 维度(计算图切片), Batch 不切                  |
| 通信传输的内容   | 传输"权重矩阵"与"梯度矩阵"                               | 传输"中间激活值 (Activations)"                                  |
| 通信发生在何时   | 每一层的计算前/后(收集权重、散播梯度)                    | 算子矩阵乘法的计算内部(算完即通信聚合)                          |
| 通信频次与颗粒度 | 粗粒度(每层通信 1~2 次大张量)                            | 极高频(每个 Linear/Attention 算子都要 All-Reduce)               |
| 对网络延迟敏感度 | 低(Latency Tolerant): 可利用 Prefetch 流完美掩盖通信延迟 | 极高(Latency Sensitive): 通信位于核心执行路径上, 强依赖超低延迟 |
| 适用网络物理拓扑 | 跨机跨节点(InfiniBand, RoCE 乃至普通以太网)均可扩展      | 仅限节点内(Single Node), 依赖 NVLink (900GB/s+) 或 NVSwitch     |
| 激活值显存占用   | 随局部 Batch 降低, 但中间层特征维度是完整的              | 中间层激活值维度缩小到 $1/N$, 自带激活值压缩效果                |

#### 2. 通信内容的深度辨析:
* FSDP2 的哲学: "数据动, 模型切碎, 计算时把模型拼起来".
  * 显存里只放 $1/N$ 的权重. 当需要计算时, 网络通信传输的是 $W$(权重参数). 算完就把全量权重丢掉.
* TP 的哲学: "模型常驻本地切片, 数据流进来在算子内部拆分, 传输拆分后的激活".
  * 网络通信传输的是 $Y = XW$(特征图/激活值). 权重永远安分地呆在当前卡上, 永远不会在卡间传递.

#### 3. 为什么业界要将它们结合(3D 并行)?
正是因为上述本质区别:
* TP 极度消耗带宽与通信延迟, 一旦跨机器(走交换机)性能就会断崖式下跌, 因此 TP Size 通常严格限制在单个机器内(如 8 卡 NVLink).
* FSDP / DDP 可以很好地重叠(Overlap)计算与通信, 容忍跨机通信的毫秒级延迟, 因此用于跨机器之间的横向扩展.

这就是大模型训练中著名的 TP (节点内 NVLink) + FSDP/ZeRO (跨节点 IB/RoCE) 混合并行架构的底层逻辑.

Q: 对于 FSDP2, 也就是 Zero-3 范式, 我理解他的前向传播和反向传播的过程如下:
1、每张卡持有 1/8 权重切片
2、将大批次的数据切片成小批次的数据作为输入
3、在前向传播时触发 All-Gather, 将所有权重收集到当前卡上, 利用输入数据进行全量计算
4、释放当前卡的权重
5、反向传播计算梯度, 再次触发 All-Gather, 本地计算全量梯度
6、释放当前卡的权重
7、触发 Reduce-Scatter, 梯度累加求和
8、优化器更新参数

我的上述描述是否正确, 特别是一些细节是否正确?
对于反向传播, 触发了 All-Gather, 本地已经计算了全量梯度, 为什么后续还要触发 Reduce-Scatter, 梯度累加求和?
多次触发 All-Gather 是合适的吗? 为什么会有触发 All-Gather 的操作?

你的 8 步总结骨架非常清晰且完全抓住了核心流程.

但在这 8 个步骤中, 存在 2 个非常关键的工程与数学细节需要精确校正; 同时, 你提出的两个追问(为什么本地算了全量梯度还要 Reduce-Scatter? 多次 All-Gather 是否合理?)直击分布式系统设计的数学本质与显存通信权衡(Trade-off).

下面我们展开深度剖析.

---

### 一、8 步流程细节校正与完整生命周期

你的 8 步流程在逻辑上是通顺的, 但需要补充粒度(Granularity)和数学语义的精确定义:

```
                    ┌───────────────────────────────────────────────────────────┐
                    │               FSDP2 单个 Transformer 层生命周期           │
                    └───────────────────────────────────────────────────────────┘
                                                  │
 ┌────────────────────────────────────────────────┴────────────────────────────────────────────────┐
 │ [前向阶段 Forward] (逐层迭代 Layer 0 -> N)                                                      │
 │  1. All-Gather 权重       : 当前卡利用 1/8 权重切片通信拼装出该层完整权重 W_full                      │
 │  2. 局部前向计算          : Y_local = X_local @ W_full                                          │
 │  3. 立即释放 (del) W_full : 显存中只保留当前层的输出激活值 (用于反向传播), 丢弃 W_full                │
 ├─────────────────────────────────────────────────────────────────────────────────────────────────┤
 │ [反向阶段 Backward](逐层逆序 Layer N -> 0)                                                      │
 │  4. 再次 All-Gather 权重  : 重新收集该层完整权重 W_full (因为反向传导 dX 时必须用到 W)              │
 │  5. 本地梯度计算          : 算出形状全量但数据局部的 ∇W_local = (X_local)^T @ ∇Y_local              │
 │  6. 立即释放 (del) W_full : 再次释放权重显存                                                     │
 │  7. Reduce-Scatter 梯度   : 跨卡累加 8 张卡的 ∇W_local, 并直接切分为 8 份, 各卡只留属于自己的 1/8  │
 ├─────────────────────────────────────────────────────────────────────────────────────────────────┤
 │ [更新阶段 Step] (全网无通信)                                                                   │
 │  8. 本地优化器更新        : 当前卡只用属于自己的 1/8 梯度更新 1/8 权重与 1/8 Adam 状态          │
 └─────────────────────────────────────────────────────────────────────────────────────────────────┘
```

#### 需要强调的 2 个细节校正:

1. 执行粒度是"逐层(Layer-by-Layer)", 而非全局全模型:
   * 如果第 3 步在模型一开始就 All-Gather 全模型参数, 显存会瞬间撑爆, FSDP 就退化成了 DDP.
   * FSDP2 是算到哪一层, 才 All-Gather 哪一层的权重, 算完这层立刻销毁.
2. 第 5 步算出的梯度是"形状全量", 但"数值局部"(这直接引出你的下一个核心疑问).

---

### 二、本地已经计算了全量梯度, 为什么还要触发 Reduce-Scatter 累加求和?

这里是理解数据并行(DP/ZeRO)最容易产生困惑的地方: 必须严格区分"张量形状(Shape)"与"数学样本量(Data Semantics)"的区别.

#### 1. 数学本质: "形状全量" $\neq$ "全局真实梯度"

假设全局 Batch Size = 16, 卡数 = 8, 每张卡拿到 Local Batch Size = 2(记为 $X_0, X_1, \dots, X_7$).
对于某一个形状为 $[2048, 8192]$ 的权重矩阵 $W$:

* 本地算出的梯度 $\nabla W_{local\_rank0}$:
  * 其矩阵形状确实是 $[2048, 8192]$(与完整参数同尺寸).
  * 但从数学上看, 它只是基于 Rank 0 上的那 2 个样本 计算出来的偏导数:
    $$\nabla W_{local\_rank0} = \frac{\partial \mathcal{L}(\text{样本 0, 1})}{\partial W}$$
* 全局需要的真实梯度 $\nabla W_{global}$:
  * 模型真正要更新依据的是 全局 16 个样本的平均梯度:
    $$\nabla W_{global} = \frac{1}{8} \sum_{i=0}^7 \nabla W_{local\_rank\_i}$$

如果不做通信累加, Rank 0 拿到的梯度只能代表 2 个样本, 模型根本无法收敛(相当于 Batch Size 萎缩了 8 倍且各卡学偏).

#### 2. 为什么是 Reduce-Scatter, 而不是 All-Reduce?

* 如果使用 `All-Reduce`(DDP 的做法):
  * 8 张卡求和平均后, 每张卡都会获得一份完整的 $[2048, 8192]$ 全局梯度.
  * 缺点: 每张卡都必须为完整的梯度分配显存, 且优化器必须维护全量的 Adam 动量状态($16 \times P$ 显存).
* 使用 `Reduce-Scatter`(FSDP2 的做法):
  * 通信硬件在求和的同时, 顺便把矩阵切碎分发:
    * Rank 0 仅接收第 0 号切片($[256, 8192]$)的全局平均梯度;
    * Rank 1 仅接收第 1 号切片($[256, 8192]$)的全局平均梯度……
  * 收益: 通信结束后, Rank 0 显存里只留下了属于自己的 $1/8$ 梯度, 完全不需要保存其他 7 张卡的梯度, 从而使梯度显存和优化器显存严格下降为原来的 $1/8$.

---

### 三、多次触发 All-Gather 是合适的吗? 为什么要触发 All-Gather?

频繁触发 All-Gather 看起来"非常昂贵", 但它恰恰是分布式深度学习中最精妙的 "以通信换显存(Memory-Communication Trade-off)" 的设计.

#### 1. 为什么会有触发 All-Gather 的操作? (为什么不直接切片算?)

`为什么不能像 TP 那样, 权重切片后各卡直接做局部矩阵乘法?`
* 线性代数的约束:
  * 在数据并行中, 输入数据 $X_{local}$ 的隐藏维度 $D$ 是完整的(形状为 $[B_{local}, S, D]$).
  * 要完成前向 $Y = X W$ 计算, 必须有完整的 $W$ 参与乘法. 由于单卡只存了 $1/8$ 行的 $W$, 在不改变计算图维度的情况下, 只能临时把其他卡上的权重"借"过来拼成完整的 $W$.

#### 2. 为什么反向传播还要"再触发一次" All-Gather?

* 反向传播计算传递给前一层的激活梯度 $\nabla X = \nabla Y \cdot W^T$ 时, 数学上必须再次用到权重矩阵 $W$.
* 为什么前向算完不把 $W$ 保存在显存里, 留给反向用?
  * 如果每层前向算完都把 $W$ 留在显存里, 那么当整网前向结束时, 所有层的 $W$ 都在显存里了.
  * 这会导致全量模型权重常驻显存, ZeRO-3/FSDP 的"参数分片"显存优化彻底失效.
  * 因此必须在前向算完立刻销毁, 反向用到时再次 All-Gather 临时拉取.

#### 3. 这种"反复 All-Gather"在性能上是划算的吗?

我们从 通信量数学分析 和 计算-通信重叠(Overlap) 两个维度来证明它的合理性:

##### (1) 通信总量分析: FSDP 仅比 DDP 多 50% 通信量!

设模型总参数量为 $P$. 在单步训练中:

* DDP 的通信:
  * 前向: $0$
  * 反向: $1$ 次梯度 `All-Reduce` $\approx 2P$ 通信量
  * 总通信量 = $2P$
* FSDP2 的通信:
  * 前向: $1$ 次权重 `All-Gather` $\approx 1P$ 通信量
  * 反向: $1$ 次权重 `All-Gather` $\approx 1P$ 通信量
  * 反向: $1$ 次梯度 `Reduce-Scatter` $\approx 1P$ 通信量
  * 总通信量 = $3P$

> 结论: FSDP2 用仅仅 $1.5 \times$ 的通信量代价, 换取了参数显存、梯度显存、优化器状态显存全部降低 $N$ 倍(例如 8 卡降低 87.5%) 的巨大红利, 使得单机训练数倍大小的模型成为可能.
>

##### (2) 预取机制(Prefetch Overlap): 将通信耗时"隐形化"

在实际工程实现(如 PyTorch FSDP2)中, All-Gather 并不是串行等待的, 而是使用 CUDA Stream 异步预取(Prefetching):

```
时间轴 ────────────────────────────────────────────────────────────────────────►
[计算流 CUDA Stream 1]:    │── 计算 Layer 1 ──│── 计算 Layer 2 ──│── 计算 Layer 3 ──│
[通信流 CUDA Stream 2]:    │── 预取 Layer 2 ──│── 预取 Layer 3 ──│── 预取 Layer 4 ──│
                           (通信与计算完全重叠, 通信耗时被计算耗时完美掩盖!)
```

当 GPU 正在计算第 1 层的矩阵乘法时, 后台通信流已经在通过 PCIe / NVLink 悄悄把第 2 层的权重 All-Gather 到 Buffer 中了. 只要计算时间大于通信时间, 多次 All-Gather 在实际耗时上几乎是"免费(Zero-overhead)"的!

### 总结全景图

| 机制节点   | 操作                  | 核心目的                                           | 显存与数据状态                    |
| :--------- | :-------------------- | :------------------------------------------------- | :-------------------------------- |
| 前向开始前 | `All-Gather` 权重     | 满足算子全维度计算需求                             | 临时占用 1 层全量权重显存         |
| 前向计算后 | `del` 释放权重        | 极致压榨显存峰值                                   | 权重瞬间回落至 $1/N$              |
| 反向开始前 | `All-Gather` 权重     | 满足计算 $\nabla X$ 的数学要求                     | 再次临时占用 1 层全量权重显存     |
| 反向计算中 | 本地求导              | 得到当前局部数据的参数梯度                         | 得到全尺寸的局部样本梯度          |
| 反向计算后 | `Reduce-Scatter` 梯度 | 数学上完成全量数据汇总, 物理上只收录属于自己的切片 | 梯度显存降为 $1/N$                |
| 优化器更新 | `Local Step`          | 各卡独立更新自己的分片                             | 完全 0 通信, 优化器显存只需 $1/N$ |
