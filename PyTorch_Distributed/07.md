### 1. 什么是 Tensor Parallelism (TP)? 具体含义是什么?

#### 核心定义

张量并行(Tensor Parallelism) 是一种层内(Intra-Layer)的分布式并行技术. 与数据并行(Data Parallel, 切分 Batch Dimension)和流水线并行(Pipeline Parallel, 按 Layer 切分网络层)不同, TP 将单个 Transformer 层内部的大型张量(如权重矩阵 $W$ 和激活值 $X$)切分到多个 GPU 上同时进行计算.

#### 数学与逻辑原理(以矩阵乘法 $Y = XW$ 为例)

TP 最早由 NVIDIA 在 Megatron-LM 论文中提出. 核心思路是将线性层(Linear Layer)的矩阵乘法拆分为以下两种基本模式:

1. 列并行(Column Parallel Linear):

   * 将权重矩阵 $W$ 按列切分为 $W_1, W_2, \dots, W_k$.

   * 输入 $X$ 被广播(Broadcast)到所有 GPU.

   * 每个 GPU 独立计算: $Y_i = X W_i$.

   * 结果 $Y = [Y_1, Y_2, \dots, Y_k]$, 按列拼接(Concat), 或保持切分状态直接传给下一层.

2. 行并行(Row Parallel Linear):

   * 输入张量按列切分为 $X_1, X_2$, 权重矩阵 $W$ 按行切分为 $W_1, W_2$.

   * 每个 GPU 计算局部结果: $Z_i = X_i W_i$.

   * 最终输出需要通过 All-Reduce (Sum) 通信原语聚合: $Y = Z_1 + Z_2 = X_1 W_1 + X_2 W_2$.

#### 在 Transformer 中的高效组合

为了减少 GPU 间高昂的通信开销, Megatron-LM 设计了极为巧秒的匹配:

* MLP 模块: 第一层 Linear 做列并行 $\rightarrow$ 激活函数(无通信) $\rightarrow$ 第二层 Linear 做行并行.

  * 通信开销: 整个 MLP 模块仅在第二层结束时需要 1 次 All-Reduce!

* Attention 模块: $Q, K, V$ 投影做列并行(按注意力头 Head 切分) $\rightarrow$ 局部自注意力计算 $\rightarrow$ Out Projection 做行并行.

  * 通信开销: 整个 Attention 模块仅需要 1 次 All-Reduce!

### 2. 为什么需要 Tensor Parallelism (TP)?

在大模型训练和推理中, TP 解决了以下几个核心痛点:

#### 1 单层权重/激活值超出单卡显存(Memory Limit)

在 70B 甚至 405B 参数的模型中, 单个 Linear 层的权重矩阵可能高达数十 GB.

* 流水线并行 (PP) 只能把不同 Layer 放到不同卡上, 如果单层模型本身加上前向传播中间激活值(Activations)超出了单张 GPU 的显存容量, PP 也无能为力.

* TP 能够将单层内巨大的权重和激活直接切碎分摊到多张卡上.

#### 2 超低延迟要求(Latency reduction for Inference)

* 在 LLM 推理(尤其生成阶段 Decode Phase, Batch Size 通常较小)中, 计算受限于显存带宽(Memory Bound).

* 数据并行(DP)无法降低单个请求的推理延迟.

* TP 将单个 Token 的计算算力分散到 N 张 GPU 上并行处理, 极大缩短了每个 Token 的生成时间, 是实现实时交互(Low-latency Streaming)的核心技术.

#### 3 消除流水线并行 (PP) 的气泡(Pipeline Bubbles)

* PP 在批处理时会产生待机等待(Bubble). TP 则是同步计算, 每个 Step 内部多卡并行, 不需要等待 Memory/Compute 槽位填充, 利用率更高.

#### 4 适合单机多卡的高带宽互联环境(NVLink)

* TP 在每一层都有频度极高的通信(如每层 2 次 All-Reduce). 这种通信频率在跨节点(以太网/InfiniBand)会极其缓慢.

* 但现代 AI 服务器单机内(如 8x H100/A100)拥有高达 900GB/s 的 NVLink, 极高的通信带宽使得 TP 在单机 8 卡范围内能够获得近乎线性的加速比. 因此 TP 通常作为 3D 并行(DP + PP + TP)中最内层(单机内)的并行策略.

### 3. 代码示例: 如何在 PyTorch 中使用 Tensor Parallel

PyTorch 从 2.0+ 开始推出了原生的 `torch.distributed.tensor.parallel`(基于 `DTensor` 构建), 使得使用 TP 变得非常优雅和模块化, 不再需要手动写繁琐的 `dist.all_reduce` 通信.

下面我展示两个维度的代码实现:

1. PyTorch 2.x 官方原生 API(推荐的高层使用方式)

2. 基于 PyTorch 自定义算子的底层原理示意(帮助深刻理解内部逻辑)

---

#### 示例 1: 使用 PyTorch 原生 `tensor.parallel` API (PyTorch 2.x+)

这是目前标准、简洁且生产可用的方式.

```python
# tp_example.py
# 运行方式: torchrun --nproc_per_node=2 tp_example.py

import os
import torch
import torch.nn as nn
import torch.distributed as dist

# 导入 PyTorch Distributed Tensor Parallel API
from torch.distributed.device_mesh import init_device_mesh
from torch.distributed.tensor.parallel import (
    parallelize_module,
    ColwiseParallel,
    RowwiseParallel,
    PairwiseParallel,
)


# 1. 定义一个标准的 Transformer MLP 模块
class ToyMLP(nn.Module):
    def __init__(self, hidden_dim: int):
        super().__init__()
        # 假设 hidden_dim -> 4 * hidden_dim -> hidden_dim
        self.in_proj = nn.Linear(hidden_dim, hidden_dim * 4, bias=False)
        self.act = nn.GELU()
        self.out_proj = nn.Linear(hidden_dim * 4, hidden_dim, bias=False)

    def forward(self, x):
        return self.out_proj(self.act(self.in_proj(x)))


def main():
    # 初始化分布式环境 (NCCL)
    dist.init_process_group("nccl")
    rank = dist.get_rank()
    world_size = dist.get_world_size()
    torch.cuda.set_device(rank)

    # 创建 DeviceMesh (设备网格), 这里定义 1D 的 TP 网格, 网格大小为 world_size
    device_mesh = init_device_mesh("cuda", mesh_shape=(world_size,))

    # 实例化普通模型
    hidden_dim = 1024
    model = ToyMLP(hidden_dim).to(f"cuda:{rank}")

    print(f"[Rank {rank}] 转换前 Linear1 权重形状: {model.in_proj.weight.shape}")

    # --- 核心: 应用 Tensor Parallelism ---
    # 方式 A: 使用预定义的 PairwiseParallel (专门优化 MLP 结构: 第一层列并行, 第二层行并行)
    tp_model = parallelize_module(
        module=model, device_mesh=device_mesh, parallelize_plan=PairwiseParallel()
    )

    # 方式 B: 也可以通过 Dict 精细化指定层:
    # tp_plan = {
    #     "in_proj": ColwiseParallel(),
    #     "out_proj": RowwiseParallel(),
    # }
    # tp_model = parallelize_module(model, device_mesh, tp_plan)

    # 查看切分后的权重形状
    # 原本 4096 x 1024 的 in_proj, 在 2 卡上切分后, 每张卡只保存 2048 x 1024
    print(
        f"[Rank {rank}] 转换后(TP) in_proj 局部权重形状: {tp_model.in_proj.weight.to_local().shape}"
    )
    print(
        f"[Rank {rank}] 转换后(TP) out_proj 局部权重形状: {tp_model.out_proj.weight.to_local().shape}"
    )

    # 前向传播测试
    input_data = torch.randn(8, 128, hidden_dim, device=f"cuda:{rank}")
    output = tp_model(input_data)

    print(f"[Rank {rank}] 输出 Shape: {output.shape}")

    dist.destroy_process_group()


if __name__ == "__main__":
    main()

```

#### 示例 2: 手动实现 Column/Row Parallel(揭秘底层通信)

如果你想了解底层是如何通过 `torch.distributed` 手动拼接张量和管理反向传播梯度的, 可以看下面这个 Megatron-style 的纯逻辑实现:

```python
import torch
import torch.nn as nn
import torch.distributed as dist


# 1. 自定义支持全收集 (All-Gather) 的 Autograd Function
class _CopyToModelParallelRegion(torch.autograd.Function):
    """前向传播不做任何事(直接 Pass), 反向传播执行 All-Reduce"""

    @staticmethod
    def forward(ctx, input_):
        return input_

    @staticmethod
    def backward(ctx, grad_output):
        # 梯度自动累加
        dist.all_reduce(grad_output, op=dist.ReduceOp.SUM)
        return grad_output


class _ReduceFromModelParallelRegion(torch.autograd.Function):
    """前向传播执行 All-Reduce, 反向传播不做任何事"""

    @staticmethod
    def forward(ctx, input_):
        dist.all_reduce(input_, op=dist.ReduceOp.SUM)
        return input_

    @staticmethod
    def backward(ctx, grad_output):
        return grad_output


# 2. 手动实现列并行 Linear (Column Parallel)
class ManualColumnParallelLinear(nn.Module):
    def __init__(self, in_features, out_features, world_size, rank):
        super().__init__()
        # 在列维度拆分 out_features
        self.out_features_per_partition = out_features // world_size
        self.weight = nn.Parameter(
            torch.empty(self.out_features_per_partition, in_features)
        )
        nn.init.kaiming_uniform_(self.weight)

    def forward(self, x):
        # 前向: X 不变, 直接与局部 Weight 做矩阵乘法
        # x: [batch, in_features]
        # weight: [out_features / k, in_features]
        # output: [batch, out_features / k]
        input_parallel = _CopyToModelParallelRegion.apply(x)
        return nn.functional.linear(input_parallel, self.weight)


# 3. 手动实现行并行 Linear (Row Parallel)
class ManualRowParallelLinear(nn.Module):
    def __init__(self, in_features, out_features, world_size, rank):
        super().__init__()
        # 在行维度拆分 in_features
        self.in_features_per_partition = in_features // world_size
        self.weight = nn.Parameter(
            torch.empty(out_features, self.in_features_per_partition)
        )
        nn.init.kaiming_uniform_(self.weight)

    def forward(self, x):
        # x 输入本身已经是被切分好的 [batch, in_features / k]
        # 局部计算 [batch, out_features]
        output_parallel = nn.functional.linear(x, self.weight)
        # 前向结束前做一次 All-Reduce, 聚合所有 GPU 的局部和
        output = _ReduceFromModelParallelRegion.apply(output_parallel)
        return output

```

### 总结比较

| 特性 / 维度 | Data Parallelism (DP)    | Pipeline Parallelism (PP)   | Tensor Parallelism (TP)                  |
| :---------- | :----------------------- | :-------------------------- | :--------------------------------------- |
| 切分维度    | Batch 维度               | 模型 Layer 层数维度         | 单层内的 Weight/Tensor 维度              |
| 通信频率    | 较低(每个 Step 结束一次) | 中等(P2P 传递 Layer 激活值) | 极高(每一层 1-2 次 All-Reduce)           |
| 硬件要求    | 普通网络/跨节点均可      | 高带宽/跨节点               | 强烈依赖 NVLink / 高带宽 intra-node 网络 |
| 适用场景    | 扩充训练 Batch Size      | 模型层数极多, 单卡装不下    | 超大单层参数、极低推理延迟要求           |

在现代大模型工程(如 DeepSpeed, Megatron-LM, vLLM, PyTorch Distributed)实践中, 我们通常将 TP 放在节点内(如 8 卡 NVLink), 将 PP / DP / ZeRO 放在节点间, 形成高效的 3D 并行混合架构.

该脚本基于 PyTorch 原生的 `torch.distributed.device_mesh` 和 `torch.distributed.tensor.parallel` API, 包含了: TP 并行化映射、同步随机数据生成、完整前反向传播训练、分布式 Checkpoint 导出与保存, 以及资源回收.

### 1. 完整 PyTorch TP 训练脚本 (`train_tp.py`)

将以下代码保存为文件 `train_tp.py`:

```python
import os
import torch
import torch.nn as nn
import torch.distributed as dist
from torch.distributed.device_mesh import init_device_mesh
from torch.distributed.tensor.parallel import (
    parallelize_module,
    ColwiseParallel,
    RowwiseParallel,
)
from torch.distributed.checkpoint.state_dict import get_model_state_dict


# -----------------------------------------------------------------------------
# 1. 原始模型定义 (保持你的模型结构不变)
# -----------------------------------------------------------------------------
class TransformerBlock(nn.Module):
    def __init__(self, dim: int):
        super().__init__()
        self.linear1 = nn.Linear(dim, dim * 4)
        self.act = nn.GELU()
        self.linear2 = nn.Linear(dim * 4, dim)

    def forward(self, x):
        return x + self.linear2(self.act(self.linear1(x)))


class SimpleLLM(nn.Module):
    def __init__(self, vocab_size=10000, dim=2048, num_layers=4):
        super().__init__()
        self.embed = nn.Embedding(vocab_size, dim)
        self.layers = nn.ModuleList([TransformerBlock(dim) for _ in range(num_layers)])
        self.head = nn.Linear(dim, vocab_size)

    def forward(self, x):
        x = self.embed(x)
        for layer in self.layers:
            x = layer(x)
        return self.head(x)


# -----------------------------------------------------------------------------
# 2. 分布式环境初始化与清理
# -----------------------------------------------------------------------------
def setup_distributed():
    """初始化分布式进程组 (NCCL)"""
    dist.init_process_group("nccl")
    local_rank = int(os.environ["LOCAL_RANK"])
    rank = int(os.environ["RANK"])
    world_size = int(os.environ["WORLD_SIZE"])
    torch.cuda.set_device(local_rank)
    return rank, local_rank, world_size


def cleanup():
    """销毁进程组, 回收 GPU 资源"""
    dist.destroy_process_group()


# -----------------------------------------------------------------------------
# 3. 主训练流程
# -----------------------------------------------------------------------------
def train():
    rank, local_rank, world_size = setup_distributed()
    device = torch.device(f"cuda:{local_rank}")

    if rank == 0:
        print(f"[Init] 开始初始化单机 {world_size} 卡 TP 训练环境...")

    # 超参数配置
    vocab_size = 10000
    dim = 2048
    num_layers = 4
    batch_size = 4
    seq_len = 128
    num_steps = 10

    # A. 创建 DeviceMesh (设备网格)
    # 对于纯 1D TP, 创建维度为 (world_size,) 的 1D Mesh
    tp_mesh = init_device_mesh("cuda", (world_size,))

    # B. 实例化原始模型并移动到当前 GPU
    model = SimpleLLM(vocab_size=vocab_size, dim=dim, num_layers=num_layers).to(device)

    # C. 应用 Tensor Parallelism (TP)
    # Megatron 风格经典方案:
    # TransformerBlock 中的 MLP: linear1 做列并行 (Colwise), linear2 做行并行 (Rowwise)
    for layer in model.layers:
        parallelize_module(
            module=layer,
            device_mesh=tp_mesh,
            parallelize_plan={
                "linear1": ColwiseParallel(),
                "linear2": RowwiseParallel(),
            },
        )

    if rank == 0:
        print("[TP Setup] 已成功为所有 TransformerBlock 应用列并行与行并行切分!")

    # D. 优化器与损失函数
    optimizer = torch.optim.AdamW(model.parameters(), lr=1e-4)
    criterion = nn.CrossEntropyLoss()

    # E. 训练循环
    model.train()
    for step in range(1, num_steps + 1):
        optimizer.zero_grad()

        # [重点]TP 模式下, 所有卡需要接收相同的 Input Batch (Data Replicated)
        # 通过固定相同的 random seed 来保证 8 张卡生成的 Dummy 数据完全一致
        torch.manual_seed(42 + step)
        input_ids = torch.randint(0, vocab_size, (batch_size, seq_len), device=device)
        targets = torch.randint(0, vocab_size, (batch_size, seq_len), device=device)

        # 前向传播
        outputs = model(input_ids)  # Shape: [batch_size, seq_len, vocab_size]

        # 计算 Loss
        loss = criterion(outputs.view(-1, vocab_size), targets.view(-1))

        # 反向传播与优化
        loss.backward()
        optimizer.step()

        if rank == 0:
            print(f"Step [{step}/{num_steps}] - Loss: {loss.item():.4f}")

    # -------------------------------------------------------------------------
    # 4. 模型保存 (Save Model State Dict)
    # -------------------------------------------------------------------------
    if rank == 0:
        print("\n[Save] 开始聚合全量模型权重并保存...")

    # PyTorch 提供 get_model_state_dict 自动将各个 GPU 上的分布式张量 (DTensor)
    # 聚合并还原为单卡/CPU 上的完整 state_dict, 屏蔽了底层切分细节
    full_state_dict = get_model_state_dict(model)

    if rank == 0:
        os.makedirs("checkpoints", exist_ok=True)
        save_path = "checkpoints/simple_llm_tp.pt"
        torch.save(full_state_dict, save_path)
        print(f"[Save] 完整模型权重已成功保存至: {save_path}")

    # 同步等待 Rank 0 完成保存操作
    dist.barrier()


# -----------------------------------------------------------------------------
# 5. 脚本入口与异常防护 (资源回收)
# -----------------------------------------------------------------------------
if __name__ == "__main__":
    try:
        train()
    finally:
        # 确保无论发生什么异常, 最终都能正确释放 PyTorch NCCL 资源
        cleanup()

```

---

### 2. 核心技术细节说明

1. 并行计划定义 (`parallelize_module`):

   * 我们遍历了 `model.layers` 中的每一个 `TransformerBlock`.

   * 对 `linear1` 使用 `ColwiseParallel()`(列并行): 权重在 $Dim \to 4 \times Dim$ 扩展维度切分为 8 份, 每卡只算 $\frac{1}{8}$.

   * 对 `linear2` 使用 `RowwiseParallel()`(行并行): 权重在 $4 \times Dim \to Dim$ 缩减维度切分为 8 份, 并在结尾自动触发 All-Reduce 通信将各卡结果求和.

2. 数据的同步处理 (Input Replication):

   * 在纯 Tensor Parallel 下, 所有 GPU 处理的 Batch 必须是一模一样的.

   * 代码中通过在每个 step 设置相同的全局 seed (`torch.manual_seed(42 + step)`), 保证 8 个进程生成的 `input_ids` 完全相同.

3. 分布式 Checkpoint 保存 (`get_model_state_dict`):

   * 由于模型参数已被转为分布式的 `DTensor`, 直接使用 `model.state_dict()` 得到的是被切碎的 Tensor.

   * 采用 PyTorch 官方的 `get_model_state_dict(model)` API, 它能在后台自动将切分的张量通过通信 Gather 回 Rank 0, 直接保存为一个无需依赖 TP 即可在单卡重新加载的标准 `.pt` 文件.

4. 资源清理与回收 (`cleanup`):

   * 使用 `try...finally` 结构包裹 `train()` 逻辑. 无论因报错中断还是正常结束, 都会确保执行 `dist.destroy_process_group()`, 释放 GPU 显存和 NCCL 套接字通信句柄.

### 1. 完整多机多卡 TP 训练脚本 (`train_multi_node_tp.py`)

将以下脚本保存为 `train_multi_node_tp.py`(两台机器上都需要放置这份完全相同的代码):

```python
import os
import torch
import torch.nn as nn
import torch.distributed as dist
from torch.distributed.device_mesh import init_device_mesh
from torch.distributed.tensor.parallel import (
    parallelize_module,
    ColwiseParallel,
    RowwiseParallel,
)
from torch.distributed.checkpoint.state_dict import get_model_state_dict


# -----------------------------------------------------------------------------
# 1. 原始模型定义 (保持结构不变)
# -----------------------------------------------------------------------------
class TransformerBlock(nn.Module):
    def __init__(self, dim: int):
        super().__init__()
        self.linear1 = nn.Linear(dim, dim * 4)
        self.act = nn.GELU()
        self.linear2 = nn.Linear(dim * 4, dim)

    def forward(self, x):
        return x + self.linear2(self.act(self.linear1(x)))


class SimpleLLM(nn.Module):
    def __init__(self, vocab_size=10000, dim=2048, num_layers=4):
        super().__init__()
        self.embed = nn.Embedding(vocab_size, dim)
        self.layers = nn.ModuleList([TransformerBlock(dim) for _ in range(num_layers)])
        self.head = nn.Linear(dim, vocab_size)

    def forward(self, x):
        x = self.embed(x)
        for layer in self.layers:
            x = layer(x)
        return self.head(x)


# -----------------------------------------------------------------------------
# 2. 跨节点分布式环境初始化与清理
# -----------------------------------------------------------------------------
def setup_distributed():
    """初始化跨节点 NCCL 进程组"""
    dist.init_process_group("nccl")

    # 环境变量由 torchrun 自动注入
    global_rank = int(os.environ["RANK"])  # 0 ~ 15
    local_rank = int(os.environ["LOCAL_RANK"])  # 0 ~ 7 (单机内的 GPU 编号)
    world_size = int(os.environ["WORLD_SIZE"])  # 16

    # 将当前进程绑定到本机的对应 GPU 上
    torch.cuda.set_device(local_rank)
    return global_rank, local_rank, world_size


def cleanup():
    """清理进程组, 释放跨节点 NCCL 连接与 GPU 资源"""
    if dist.is_initialized():
        dist.destroy_process_group()


# -----------------------------------------------------------------------------
# 3. 主训练流程
# -----------------------------------------------------------------------------
def train():
    global_rank, local_rank, world_size = setup_distributed()
    device = torch.device(f"cuda:{local_rank}")

    if global_rank == 0:
        print(f"[Init] 成功建立跨节点集群! 总卡数 (WORLD_SIZE): {world_size}")

    # 超参数配置
    vocab_size = 10000
    dim = 2048
    num_layers = 4
    batch_size = 4
    seq_len = 128
    num_steps = 10

    # A. 初始化 1D DeviceMesh, 将 16 张 GPU 编排在同一个 TP 网格中
    tp_mesh = init_device_mesh("cuda", (world_size,))

    # B. 实例化模型并移动到本地 GPU
    model = SimpleLLM(vocab_size=vocab_size, dim=dim, num_layers=num_layers).to(device)

    # C. 应用跨 16 卡的 Tensor Parallelism
    # 将矩阵切分为 16 份 (Colwise) 和 16 份 (Rowwise)
    for layer in model.layers:
        parallelize_module(
            module=layer,
            device_mesh=tp_mesh,
            parallelize_plan={
                "linear1": ColwiseParallel(),
                "linear2": RowwiseParallel(),
            },
        )

    if global_rank == 0:
        print(
            f"[TP Setup] 已在全部 {world_size} 张 GPU 上完成层内张量切分 (16-way TP)!"
        )

    # D. 优化器与损失函数
    optimizer = torch.optim.AdamW(model.parameters(), lr=1e-4)
    criterion = nn.CrossEntropyLoss()

    # E. 训练循环
    model.train()
    for step in range(1, num_steps + 1):
        optimizer.zero_grad()

        # [重点]TP 模式要求全网 16 张 GPU 必须接收完全相同的输入 Batch
        # 跨节点保证随机种子一致:
        torch.manual_seed(42 + step)
        input_ids = torch.randint(0, vocab_size, (batch_size, seq_len), device=device)
        targets = torch.randint(0, vocab_size, (batch_size, seq_len), device=device)

        # 前向传播 (跨节点 16 卡同步计算与 All-Reduce 通信)
        outputs = model(input_ids)

        # 计算 Loss
        loss = criterion(outputs.view(-1, vocab_size), targets.view(-1))

        # 反向传播与优化
        loss.backward()
        optimizer.step()

        if global_rank == 0:
            print(f"Step [{step}/{num_steps}] - Loss: {loss.item():.4f}")

    # -------------------------------------------------------------------------
    # 4. 跨节点权重聚合与模型保存
    # -------------------------------------------------------------------------
    if global_rank == 0:
        print("\n[Save] 开始跨节点收集 16 卡权重并还原为完整模型...")

    # get_model_state_dict 会在后台将分散在 2 台机器 16 张 GPU 上的 DTensor 汇总到 Global Rank 0
    full_state_dict = get_model_state_dict(model)

    # 仅由 Node 0 的 Rank 0 写入磁盘, 避免多节点文件写入冲突
    if global_rank == 0:
        os.makedirs("checkpoints", exist_ok=True)
        save_path = "checkpoints/simple_llm_multi_tp.pt"
        torch.save(full_state_dict, save_path)
        print(f"[Save] 跨节点聚合后的完整权重已成功保存至: {save_path}")

    # 全局同步, 防止主节点保存完后子节点提前退出导致通信中断
    dist.barrier()


# -----------------------------------------------------------------------------
# 5. 入口与资源回收
# -----------------------------------------------------------------------------
if __name__ == "__main__":
    try:
        train()
    finally:
        cleanup()

```

### 3. 高级调优与网络注意事项(生产环境必看)

   ```bash
   export NCCL_IB_DISABLE=0
   ```

   如果第一次建立跨节点连接遇到卡住(Hang 住)的情况, 可以在启动命令前加入 `NCCL_DEBUG` 排查通信握手问题:

   ```bash
   NCCL_DEBUG=INFO torchrun --nnodes=2 ... train_multi_node_tp.py
   ```

```python
    finally:
        # 使用 try...finally 结构, 确保脚本报错或中断时也能成功销毁进程组, 回收显存
```

### 2. 核心逻辑解析

1. 并行配置 (`parallelize_module`):

   * 原始 `linear1` 的权重尺寸为 `[8192, 2048]`, 在 8 卡列并行后, 每张卡实际保存的局部权重尺寸仅为 `[1024, 2048]`(显存仅占原来的 1/8).

   * 原始 `linear2` 的权重尺寸为 `[2048, 8192]`, 在 8 卡行并行后, 每张卡实际保存的局部权重尺寸为 `[2048, 1024]`.

2. 输入同步 (Data Replication):

   * TP 的本质是"单数据、多算子并行". 因此在每个 step 训练时, 通过 `torch.manual_seed(42 + step)` 确保 8 张卡上生成的 `input_ids` 和 `targets` 保持完全相同.

3. 模型保存 (`get_model_state_dict`):

   * 直接对带有 TP 的模型使用 `torch.save(model.state_dict())` 保存的是切碎的张量片段.

   * 使用官方的 `get_model_state_dict(model)` API 能够自动将 8 张卡上的 `DTensor` 全局收集并恢复为普通的 `torch.Tensor`, 保存出的 `.pt` 权重文件后续可以直接在任意单卡上恢复使用.

```python
        self.linear2 = nn.Linear(dim * 4, dim)

    def forward(self, x):
        return x + self.linear2(self.act(self.linear1(x)))


class SimpleLLM(nn.Module):
    def __init__(self, vocab_size=10000, dim=2048, num_layers=4):
        super().__init__()
        self.embed = nn.Embedding(vocab_size, dim)
        self.layers = nn.ModuleList([TransformerBlock(dim) for _ in range(num_layers)])
        self.head = nn.Linear(dim, vocab_size)

    def forward(self, x):
        x = self.embed(x)
        for layer in self.layers:
            x = layer(x)
        return self.head(x)
```

这是一份专为 2 台机器 × 每台 8 张 GPU(共 16 张 GPU) 打造的跨节点(Multi-Node)Tensor Parallelism (TP) 完整训练脚本.

在多机多卡场景下, PyTorch 代码内部的 TP 切分逻辑与单机完全一致(`init_device_mesh("cuda", (16,))` 会自动将 16 张 GPU 编排进同一个全局通信网格中). 真正的关键差异在于跨节点的分布式拉起命令(`torchrun` 的多机配置参数).

### 1. 完整跨节点训练脚本 (`train_tp_multi_node.py`)

请将以下代码保存为 `train_tp_multi_node.py`, 并确保两台机器上都放置了这份完全相同的代码:

```python
import os
import torch
import torch.nn as nn
import torch.distributed as dist
from torch.distributed.device_mesh import init_device_mesh
from torch.distributed.tensor.parallel import (
    parallelize_module,
    ColwiseParallel,
    RowwiseParallel,
)
from torch.distributed.checkpoint.state_dict import get_model_state_dict


# -----------------------------------------------------------------------------
# 1. 原始模型定义 (结构保持不变)
# -----------------------------------------------------------------------------
class TransformerBlock(nn.Module):
    def __init__(self, dim: int):
        super().__init__()
        self.linear1 = nn.Linear(dim, dim * 4)
        self.act = nn.GELU()
        self.linear2 = nn.Linear(dim * 4, dim)

    def forward(self, x):
        return x + self.linear2(self.act(self.linear1(x)))


class SimpleLLM(nn.Module):
    def __init__(self, vocab_size=10000, dim=2048, num_layers=4):
        super().__init__()
        self.embed = nn.Embedding(vocab_size, dim)
        self.layers = nn.ModuleList([TransformerBlock(dim) for _ in range(num_layers)])
        self.head = nn.Linear(dim, vocab_size)

    def forward(self, x):
        x = self.embed(x)
        for layer in self.layers:
            x = layer(x)
        return self.head(x)


# -----------------------------------------------------------------------------
# 2. 跨节点分布式环境初始化与清理
# -----------------------------------------------------------------------------
def setup_distributed():
    """初始化跨节点 NCCL 进程组"""
    dist.init_process_group("nccl")

    # 环境变量由各节点上的 torchrun 自动传入
    global_rank = int(os.environ["RANK"])  # 全局卡号: 0 ~ 15
    local_rank = int(os.environ["LOCAL_RANK"])  # 本机卡号: 0 ~ 7
    world_size = int(os.environ["WORLD_SIZE"])  # 全局总卡数: 16

    # 锁定当前进程使用的本机 GPU 编号
    torch.cuda.set_device(local_rank)
    return global_rank, local_rank, world_size


def cleanup():
    """销毁进程组, 释放跨节点通信套接字与 GPU 显存"""
    if dist.is_initialized():
        dist.destroy_process_group()


# -----------------------------------------------------------------------------
# 3. 主训练流程
# -----------------------------------------------------------------------------
def train():
    global_rank, local_rank, world_size = setup_distributed()
    device = torch.device(f"cuda:{local_rank}")

    # 仅由全局主节点 (Global Rank 0) 打印日志
    if global_rank == 0:
        print(f"[Init] 成功建立跨节点集群! 全局总卡数 (WORLD_SIZE): {world_size}")

    # 超参数定义
    vocab_size = 10000
    dim = 2048
    num_layers = 4
    batch_size = 4
    seq_len = 128
    num_steps = 10

    # A. 构建跨 16 卡的 1D 设备网格 (DeviceMesh)
    # PyTorch 会自动根据通信链路将 2 台机器的 16 张 GPU 映射为一维网格
    tp_mesh = init_device_mesh("cuda", (world_size,))

    # B. 实例化模型并移动到对应的本地 GPU 设备
    model = SimpleLLM(vocab_size=vocab_size, dim=dim, num_layers=num_layers).to(device)

    # C. 为模型应用 16-way Tensor Parallelism
    # 将线性层权重切分为 16 份 (列并行/行并行)
    for layer in model.layers:
        parallelize_module(
            module=layer,
            device_mesh=tp_mesh,
            parallelize_plan={
                "linear1": ColwiseParallel(),
                "linear2": RowwiseParallel(),
            },
        )

    if global_rank == 0:
        print(f"[TP Setup] 已在全网 {world_size} 张 GPU 上完成张量并行切分!")

    # D. 定义优化器与损失函数
    optimizer = torch.optim.AdamW(model.parameters(), lr=1e-4)
    criterion = nn.CrossEntropyLoss()

    # E. 训练循环
    model.train()
    for step in range(1, num_steps + 1):
        optimizer.zero_grad()

        # [重点]TP 属于张量并行, 要求全网 16 张 GPU 处理完全相同的输入 Batch
        # 通过统一的随机种子保证 16 张卡上的输入 Tensor 完全一致:
        torch.manual_seed(42 + step)
        input_ids = torch.randint(0, vocab_size, (batch_size, seq_len), device=device)
        targets = torch.randint(0, vocab_size, (batch_size, seq_len), device=device)

        # 前向传播 (触发跨节点的列并行矩阵乘法与行并行 All-Reduce 通信)
        outputs = model(input_ids)

        # 计算 Loss
        loss = criterion(outputs.view(-1, vocab_size), targets.view(-1))

        # 反向传播与梯度更新
        loss.backward()
        optimizer.step()

        if global_rank == 0:
            print(f"Step [{step:02d}/{num_steps:02d}] - Loss: {loss.item():.4f}")

    # -------------------------------------------------------------------------
    # 4. 跨节点权重聚合与模型保存
    # -------------------------------------------------------------------------
    if global_rank == 0:
        print("\n[Save] 开始跨节点收集 16 张卡上的切分权重并还原...")

    # get_model_state_dict 在后台通过通信将分布在 2 台机器上的 16 份 DTensor
    # 全局收集并拼回为单卡/CPU 格式的完整权重字典
    full_state_dict = get_model_state_dict(model)

    # 仅由 Node 0 的 Global Rank 0 负责落盘, 避免多机器竞争写文件
    if global_rank == 0:
        os.makedirs("checkpoints", exist_ok=True)
        save_path = "checkpoints/simple_llm_multi_node_tp.pt"
        torch.save(full_state_dict, save_path)
        print(f"[Save] 完整模型已成功保存至: {save_path}")

    # 全局同步屏障, 确保所有节点都等待主节点保存完毕
    dist.barrier()


# -----------------------------------------------------------------------------
# 5. 主程序入口与异常资源回收
# -----------------------------------------------------------------------------
if __name__ == "__main__":
    try:
        train()
    finally:
        # 使用 try...finally 防护, 确保脚本无论正常结束还是中断, 都能销毁 NCCL 进程组
        cleanup()

```

### 2. 如何运行多机多卡脚本?

假设你的网络环境配置如下:

* 机器 1(主节点 Node 0): IP 为 `192.168.1.100`, 拥有 8 张 GPU.

* 机器 2(从节点 Node 1): IP 为 `192.168.1.101`, 拥有 8 张 GPU.

* 通信主端口: `29500`(确保防火墙允许该端口通信).

#### 步骤 1: 检查环境与代码

1. 确保两台机器上都安装了相同版本的 Python 和 PyTorch.

2. 将 `train_tp_multi_node.py` 脚本放置在两台机器相同的目录路径下.

#### 步骤 2: 在[机器 1 (Node 0)]上启动主进程

在机器 1 的终端运行:

```bash
torchrun \
    --nnodes=2 \
    --nproc_per_node=8 \
    --node_rank=0 \
    --master_addr=192.168.1.100 \
    --master_port=29500 \
    train_tp_multi_node.py
```

#### 步骤 3: 在[机器 2 (Node 1)]上启动从进程

在机器 2 的终端运行:

```bash
torchrun \
    --nnodes=2 \
    --nproc_per_node=8 \
    --node_rank=1 \
    --master_addr=192.168.1.100 \
    --master_port=29500 \
    train_tp_multi_node.py
```

### 3. 多机训练的关键参数与排坑指南

1. `torchrun` 跨节点参数详解:

   * `--nnodes=2`: 指定集群中总共有 2 台机器.

   * `--nproc_per_node=8`: 每台机器上启动 8 个进程(各自占用 8 张卡).

   * `--node_rank=0` 与 `--node_rank=1`: 区分机器编号, 主节点固定为 `0`.

   * `--master_addr` 和 `--master_port`: 主节点的 IP 和端口, Node 1 会主动握手连接这个地址.

2. 跨节点网络接口设置 (`NCCL_SOCKET_IFNAME`):

   如果机器上有多个网卡(如既有普通网卡 `eth0`, 又有 RoCE/InfiniBand 网卡 `ib0`), NCCL 可能会连错网卡导致程序在握手阶段卡死(Hang 住). 建议在运行命令前显式指定通信网卡:

   ```bash
   # 指定走局域网网卡(例如 eth0):
   export NCCL_SOCKET_IFNAME=eth0

   # 如果有 IB 物理网卡, 开启 RDMA 高速通信:
   export NCCL_IB_DISABLE=0
   ```

3. 数据一致性 (Input Replication):

   TP 模式下, 全网所有的 GPU 算子属于同一次前向计算图的分块. 因此代码中通过 `torch.manual_seed(42 + step)` 保证了 2 台机器共 16 张 GPU 在每一个 step 生成的 `input_ids` 绝无差异.
